# 후보자 기본정보 동시 저장 충돌 보호

- SQL 024에 row_version과 변경 시 자동 증가 트리거, 버전 검증 저장 RPC v2를 준비했다. 실제 DB 적용 대기.
- 조회 시 버전 저장 → 저장 RPC에서 행 잠금 → 현재 버전 비교 → 일치할 때만 업데이트. 고객 기본정보 수정·보관·복원·이관 보완 모두 후보자 버전 변경을 유발한다.
- 충돌 SQLSTATE 40001 응답은 재시도/강제 덮어쓰기하지 않고 미저장 입력을 유지한다. 최신 값 조회는 접근이력 RPC를 사용한다.
- 비교 표에 내 입력과 최신 DB 값의 차이를 표시한다. 최신 정보 불러오기는 확인 후 입력·사유를 초기화하며, 조회 실패 시 내 입력을 유지한다.
- 저장 중 기본정보 입력을 비활성화해 저장 결과와 입력 화면이 달라지는 것을 방지한다.
- 024 적용 전에는 기존 RPC를 사용하고 적용 대기 안내를 표시한다. 버전 열이 있는 경우 v2 실패를 구형 RPC로 우회하지 않는다.
- 024 적용 후 구형 RPC 실행 권한은 제거한다. 호환 코드 배포를 확인한 뒤 SQL을 적용해야 하며 이전 버전 페이지는 새로고침해야 한다.
- 이것은 동시 열람·입력을 금지하는 독점 편집 잠금이 아니라 저장 충돌 검사다. 기존 신청 작업화면의 편집 잠금과 구분한다.
- 브라우저의 비교 값은 보조 정보이며 권한·버전 검사는 DB가 수행한다. 관리자 DB 유지보수/직접 SQL 권한까지 제한하는 기능은 아니다.

검증: 자동 폼 비교 검사 8개 및 SQL 구조 검사 6개, 타입/빌드 검사. 실제 두 직원/두 탭 동시 요청 시험은 SQL 적용 이후 별도로 수행한다.
