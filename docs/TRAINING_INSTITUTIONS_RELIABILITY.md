# 지정 연수기관 저장 안정성

신규 기관 선택은 기관 ID를 값으로 사용하고 업무 입력 JSON에 providerInstitutionId 및 providerDesignationNo를 기관명과 함께 저장한다. 같은 이름 기관도 지정번호로 구분해 선택한다. 기관 종류를 바꾸면 ID와 지정번호를 지운다. 저장된 기관명은 당시 기록으로 유지하고 명단 조회로 자동 변경하지 않는다.

기존 이름 기반 연결은 공백 제거 및 유니코드 정규화 후 한 기관만 확인될 때에만 화면의 명단 정보를 참조한다. 자동으로 ID를 저장하지 않는다. 이름이 중복되거나 저장된 ID가 없어진 경우 기존 이름은 선택 불가 항목으로 보존하며 첫 번째 기관의 지정번호를 임의로 표시하지 않는다. 서버 측 지정 여부 검증과 과거 유효기간 스냅샷 저장은 별도이다.

공유 DB 모드에서는 인증·권한·기관 명단 조회 실패를 로컬 샘플로 대체하지 않는다. 명단은 정확한 건수와 고유 ID를 확인하며 분할 조회한다.

등록·수정 및 활성 상태 변경은 반환된 실제 행을 검증한 뒤 화면에 반영한다. 활성 상태 변경은 조회 당시 상태를 조건으로 사용한다. 응답이 없거나 통신이 실패하면 입력을 유지하고 재조회 전 추가 저장을 제한한다. 이때 DB 저장 자체가 실패했다고 단정하지 않는다.

중복 클릭 방지와 예외 발생 시 저장 중 상태 해제를 적용한다. 로컬 가상 모드에서는 브라우저 저장이 성공한 후에만 화면을 변경한다.

자동 검사는 실제 저장 처리 함수를 추출해 정상 응답, 통신 예외, 잘못된 응답, 권한 제한, 중복 클릭 및 로컬 저장 실패를 확인한다. 실제 운영 DB의 RLS 권한 검증과 여러 직원의 동시 수정 시험은 별도이다. DB 구조 변경은 없다.

조회 중·조회 실패는 빈 목록이나 0건으로 표시하지 않고 건수 미확정으로 구분한다. 조회 실패 중에는 목록의 수정 작업을 노출하지 않는다. 실제 조회 effect를 추출한 검사로 501건 분할 조회, 인증·권한 조회 실패, 손상된 행, 화면 종료 후 응답 무시, 일반 직원의 조회 및 로컬 가상 모드 분리를 확인한다.

신청 상세의 기관 선택도 공유 DB에서는 로컬 샘플로 대체하지 않는다. 정확 건수 분할 조회·행 검증·화면 종료 보호와 재조회 버튼을 적용한다.  기존의 접수일 유효기간·활성 상태·표준 필터는 유지한다. 현재 목록에 부합하지 않는 기존 지정 기관 기록은 안내만 하고 교육·시험 기록을 자동 변경하지 않는다. 신규 ID 연결은 업무 입력 JSON에 저장하며 DB 컬럼 변경은 없다. 실제 운영 DB 저장 및 서버 측 지정 여부 검증은 별도이다.
