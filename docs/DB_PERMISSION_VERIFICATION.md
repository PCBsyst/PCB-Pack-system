# 가상 DB 권한 검증 (2026-10-05)

실행: `scripts/test-area-management-db.ps1 -Permissions`

기존 SQL 001·016·018·019·023·025·026을 격리된 Docker DB에 적용하고 `SET ROLE authenticated`로 실제 RLS를 검사했습니다. 권한 함수는 실제 코드를 사용하며, auth.uid()/auth.jwt() 입력만 가상 JWT 값으로 공급합니다. 운영 데이터·백업은 읽지 않고 종료 시 임시 컨테이너를 제거합니다.

확인 항목:

- 실무자: 고객 조회·등록·개인정보 접근기록 생성·보관 허용. 자기 승격, 고객 삭제, 수정사유 없는 변경, MFA 정책 변경 차단.
- 서브관리자: 초대 권한 함수 허용, 최고관리자 권한 함수 거절, 타 계정 활성화 차단.
- 비활성 계정: 고객 조회 결과 없음, 등록 차단. 자기 계정 정보만 조회 가능.
- 최고관리자: 개인정보 접근이력 조회, 타 계정 활성화/비활성화, 사유와 기존 설정 버전에 따른 MFA OFF 허용. 자기 비활성화 차단.
- MFA ON: aal1 고객 접근 차단. MFA OFF: 활성 실무자의 aal1 접근 허용, 비활성 계정은 계속 차단.
- 익명: 고객 조회 결과 없음. 클라이언트의 문서응답 접근이력 위조 함수 실행 및 MFA 테이블 직접 수정 권한 없음.

검증 범위 밖: 실제 로그인·JWT 서명·MFA 인증 과정·이메일 초대 발송, 직원 이메일 변경 서비스 API, 전체 마이그레이션 조합, 실제 배포 DB의 정책/권한 드리프트. 이 결과는 운영 보안 검증 완료 선언이 아닙니다. 이번 작업은 검사 코드만 추가했고 운영 DB에는 SQL을 적용하지 않았습니다.
