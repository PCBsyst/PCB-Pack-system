# 업무 투입 전 진행 현황 — 2026-10-04

전체 약 70%는 요구사항·코드·검증 상태를 기준으로 한 추정이며, 운영 승인이나 실제 DB 검증 완료를 뜻하지 않는다. 실무자 테스트와 이관까지 포함한 완료 기준이다. Dropbox 연동은 후순위로 제외한다.

## 구현된 큰 구조

- 신청 → 후보자 → 분야별 Job → 서류검토 → 청구·입금 → 심의·대표자 승인 → 발행 정보 → 패키지의 연결 구조.
- 직원 초대·역할 구분, 후보자 수정·보관 흐름, 접근·변경 이력, MFA 및 미사용 세션 보호 코드.
- 세 Word 문서 생성, 저장 원본 대조, 파일 무결성 및 전체/부분 패키지 이력 구분.
- 목록 필터·현황, 지정 연수기관, 교육·시험 일정 입력, 화면 테마와 보고 집계 기반.

## 남은 핵심 작업

1. 문서 완성: 국문·영문 세트의 미등록 양식, 필수 항목 대조와 실제 출력 배치 확인, PDF 일괄 생성.
2. 운영 보안: 적용 대기 SQL 확인, 직원 역할별 실제 DB 접근·비활성 계정 차단·감사 이력 검증. 15일 신뢰 기기와 계정 복구는 미완료.
3. 백업 운영: 짧은 주기 자동 실행, 외부 보호 보관, 보존 기간·실패 이메일, 정기 복원 시험. 현재 수동 백업/격리 복원 시험과 구분해야 한다.
4. 통계 정합성: 과거 월말 인증 상태 추이와 실제 수익 배분 기준 검증.
5. 이관: 전체 구글 시트 매핑·중복/불명확 기록 검토, 대조 및 병행 운영 후 전환.
6. 실무 검증: 직원이 신규·갱신·전환·인정/비인정 사례를 실제 세션에서 끝까지 검증.

## 이번 문서 입력 보호

교육·시험 일정은 저장값 그대로 생성한다. 입력이 존재하면 선택 Job의 기관 구분·명칭·날짜 형식을 검사하며, 불가능한 날짜와 구성 오류를 생성 전에 거절한다. 빈 날짜를 사실로 채우거나 날짜 순서를 새로 계산하지 않는다. 이전 업무기록에 일정 항목 자체가 없는 경우는 호환하되, 저장된 일정이 있는데 요청에서 누락한 경우 저장값 대조 단계에서 차단한다.

## 진행 원칙

불필요한 화면 세분화 대신 위 핵심 작업을 묶어서 진행한다. 사용자가 직접 해야 하는 인증·운영 설정은 별도로 모으고, 배포 성공과 실제 업무 검증 완료를 구분하여 보고한다. 기존 문서의 과거 상태 표는 작성 당시 기록이므로 현재 완료 상태로 그대로 사용하지 않는다.

## 문서 생성 경로의 묶음 검증 결과

`scripts/test-document-routes-output.mjs`는 실제 세 문서 API의 코드를 가상 입력과 내장 양식으로 실행한다. 국·영문 데이터 매핑, 날짜·교육기관·의견 포함, XML 특수문자 처리, 미선택 위원 제외를 확인했다. 기본 양식에서 빠지던 대표자 최종 승인 의견을 보완했고, 전용 칸이 있는 시험용 양식에서는 중복 없이 출력됨을 확인했다.

세 경로마다 권한 부족(403), 저장값 불일치(409), 손상 양식(503), 접근이력 기록 실패(503)를 모의한 12개 경우에 Word 다운로드 헤더 없이 실패 응답을 반환했다. 이 검사는 서버 경로의 분기·출력 검증이며, 인증·DB·양식 저장소·접근이력 저장은 모의한다. 운영 RLS·실제 사용자 세션·인쇄 배치·미등록 국영문 양식 완성을 증명하지 않는다.
