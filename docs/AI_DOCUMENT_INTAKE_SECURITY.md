# 신청서 자동 입력: 구현 전 보호 기준

상태(2026-11-20): 신청 상세의 서류검토 화면에 증빙 대조·경력·심사이력 분석 연결. 로컬 DOCX 텍스트 읽기와 일부 기본정보 추출, 직원 입력/확인 및 기존 업무기록 저장 연결을 구현함. AI/OCR API 및 외부 전송은 아직 활성화하지 않음.

## 현재 제공 범위와 검증 한계

- 문서별 기본정보와 등록된 후보자 정보의 일치·불일치·날짜 오류·미확인을 구분한다. 명시적인 Word 기본정보 라벨만 추출하고, PDF·이미지·스캔 OCR 및 학력·경력 표 자동 추출은 아직 제공하지 않는다. 자동 분류를 가장하지 않고 직원이 문서 종류를 선택한다.
- 근거 문서·근거 위치·후보자명·기간·기관/직무 등을 확인한 경력만 집계한다. 시작·종료일을 모두 포함한 달력 일수의 합집합으로 중복 기간을 제외한다. 재직 중은 명시적으로 선택한 경우에만 접수일을 종료 기준으로 사용한다. 경력 연수 또는 분야별 자격 충족 판정으로 간주하지 않는다.
- 심사 대상·표준·기간이 같은 기록은 중복 의심 건으로 묶는다. 같은 건의 일수가 다르거나 서로 다른 건의 날짜가 겹치면 원문 대조 완료를 선택해도 확인 합계에 포함하지 않는다. 날짜만으로 반일 심사 일정의 병행 가능 여부를 추정하지 않는다. 증빙을 확인해 기간·일수를 정정해야 한다.
- 심사일수는 직원이 입력한 양수 일수를 사용하고 달력 기간을 초과하면 제외한다. 표준별 확인 건수와 일수를 제공한다. 기록 수정 시 해당 행의 원문 대조 완료를 해제한다.
- 원본 파일과 전체 Word 본문은 서버·업무기록에 전송/저장하지 않는다. 브라우저 메모리의 본문은 해당 패널 종료 시 폐기한다. 추출된 일부 필드·문서명·파일 해시·직원 입력 이력은 기존 보호된 업무기록에 저장한다. 원본 보관 기능은 별도이며 이 연결을 원본 업로드 완료로 표시하지 않는다.
- 공유 DB가 설정된 운영 환경에서 샘플 신청의 신규 입력을 제한한다. 개발 가상 모드는 기존 브라우저 저장을 사용하므로 실제 개인정보를 입력하지 않도록 명시한다. 가상 예제는 해당 신청의 저장값과 분리한다.
- 자동 회귀검사 및 가상 브라우저의 DOCX 읽기·표 추출·예제 격리·저장/재조회·전체 본문 미저장을 검증한다. 운영 DB에서의 실제 권한·감사 기록 확인과 외부 AI 보관 조건 검증은 별도다. 이번 분석은 정식 심의 결과 또는 패키지 완료를 자동 변경하지 않는다.

## 목적과 경계

### 신규 신청등록 연결 및 검증 (2026-11-20)

후속 확장: DOCX의 `신청표준`/`신청분야`/`Standard`, `신청등급`/`Grade` 등 명시된 라벨에서 표준·등급을 대조한다. 현재 분야·인정기구·인정구분에서 사용 가능한 확정 번호 규칙의 표준만 선택하며, 사용자 추가 인증분야도 같은 목록을 사용한다. 공백·대소문자 외에는 표준명을 추정하지 않는다. 국문 ISO 등급은 기존 영문 등급에 대응시키며 ISO와 K-Beauty 등급을 혼용하지 않는다.

복수 값·미등록 값은 자동 선택하지 않는다. 직원이 원문에 맞게 직접 선택하고 별도 확인한 경우에만 `확인한 표준·등급 Job 추가`로 신청 목록에 추가한다. 이 과정은 신규 Job 저장이나 인증 승인이 아니다. 기존 Job을 덮어쓰지 않으며 같은 표준의 중복 추가를 막는다. 분야·인정기구·인정구분 또는 목록 준비 상태가 읽을 때와 달라지면 다시 읽도록 차단하고, 반영 직전에도 현재 등록 목록을 재검증한다. 기본정보 반영 시 본문이 폐기되므로 필요한 Job을 먼저 확인해 추가한다. 복수 표준·등급의 행별 자동 연결은 하지 않는다.

가상 브라우저에서 ISO 45001·선임심사원을 Lead Auditor Job으로 추가, 중복 차단, 설정 변경 차단, 복수 표준·등급 자동 선택 보류 및 등록·재조회를 검증했다. 검사 도구도 인증분야 목록 준비가 끝나 파일 선택이 활성화된 뒤 읽도록 한다. 추가 SQL이나 외부 AI 호출은 없다.

신청관리 → 신규 신청등록 → 신규 후보자에서 DOCX 읽기 패널을 제공한다. 로컬 규칙 추출이며 AI가 아니다. 이름·영문명·생년월일·국적·이메일·전화번호의 명시된 라벨을 읽는다. PDF·이미지·스캔과 실제 원본 업로드는 아직 지원하지 않는다.

읽은 본문과 추출 항목을 나란히 표시하고 모든 항목은 미승인으로 시작한다. 직원이 값을 수정하면 해당 항목의 확인을 해제한다. 기존 값과 다른 항목은 별도 변경 확인이 필요하다. 대조 중 선택 항목의 신청 입력값이 변경되면 반영하지 않고 다시 읽도록 안내한다. 생년월일·이메일·길이·제어문자 등은 기존 등록 검증을 적용한다. 복수 값 발견 시 빈 값과 상충 안내를 표시해 임의 선택하지 않는다.

선택 반영은 입력란 변경이며 DB 저장이 아니다. 기존 신청 등록 버튼과 검증을 그대로 거친다. 기등록 후보자 모드에는 패널을 제공하지 않아 기존 정보 변경 절차를 우회하지 않는다. 반영·자료 폐기·모드 전환·화면 종료 시 읽은 본문을 폐기한다. 파일명·본문·근거·미승인 값은 새 저장소나 로그에 저장하지 않는다. 승인해 입력란에 반영한 기본정보는 기존 신청 등록 경로에 저장된다. 이번 연결에는 별도 원본 보관 또는 추출 출처 감사기록 저장 기능을 추가하지 않았다.

가상 DOCX 브라우저 검사에서 미승인 제외, 기존 값 변경 확인, 대조 중 수동 수정 차단, 원문 폐기, 모드 전환, 손상 파일 이후 재시도, 신청/Job 등록 및 새로고침 후 재조회를 확인했다. 원문 전용 표식이 브라우저 저장에 없는 것과 외부 요청 0건을 확인했다. 이는 개발 가상 저장 검증이며 운영 DB/RLS/감사 검증, 실제 양식 정확도, PDF/OCR 및 외부 제공업체 처리 검증을 대신하지 않는다. 고객 자료나 실제 정보에서 변형한 예시는 사용하지 않았다.

OpenAI API의 이미지·문서 입력 및 구조화 출력 지원 모델을 사용해 신청서 기본정보를 추출한다. 특정 모델은 가상 샘플 정확도·비용 검증 후 계정에서 허용한 모델로 고정한다. AI는 승인·심의·합격 판정, 날짜 산정, 후보자 생성 또는 기존 후보자 정보 변경을 직접 수행하지 않는다.

첫 적용은 신청서 1개 → 후보자 기본정보 추출 → 원문 근거 대조 → 직원 선택 및 수정 → 기존 신청등록 절차로 제한한다. 계약서·학력·경력·교육·심사이력은 추후 문서별 허용 필드를 별도로 정의한다. 여러 후보자를 혼합 처리하지 않는다.

## 보호 대상과 양식 개선용 자료의 분리 (2026-11-19 사용자 확정)

보호 대상은 이름(국·영문), 생년월일, 전화번호, 이메일, 집주소, 경력 사항, 학력 사항 및 이들과 연결된 문서·추출문·원문 근거이다. 회사명·학교명·직위·재직/재학 기간의 조합으로 개인을 식별할 수 있는 경우도 보호한다. 국적 등 기존 후보자 정보도 같은 보호 경계에 둔다. 파일명·이미지 메타데이터·주석·변경이력·머릿글/바닥글에 포함된 개인정보도 대상이다.

일반 업무화면의 개인정보는 기존 결정에 따라 권한 있는 실무자가 조회할 수 있다. 이는 외부 AI 전송·학습·개발용 복제 권한을 의미하지 않는다.

| 자료 | 목적 및 처리 기준 |
| --- | --- |
| 실제 후보자 원본·추출값·근거 | 해당 후보자의 신청정보 확인과 업무 처리에만 사용. 일반 모델 학습, 파인튜닝, 공유 평가 데이터 또는 개선용 예시에 자동 편입하지 않음 |
| 빈 신청서·항목 정의·매핑 규칙 | 성명 칸에는 이름, 교육정보 칸에는 기관·과정·수료일 등이 들어간다는 구조를 정의. 개인정보 없이 버전 관리 |
| 가상 작성 예시 | 양식 인식·정확도 검증에 사용. 실제 경력이나 학력을 조금 변경해 만든 예시는 기본 금지하고 완전 가상 정보로 작성 |
| 직원의 수정 결과 | 해당 신청 기록 및 기존 정정 이력으로 관리. AI 피드백 전송·학습 데이터 수집·프롬프트 예시 재사용은 자동 수행하지 않음 |

모델을 추가 학습시키지 않고도 빈 양식, 추출 항목 정의, 가상 예시를 요청에 제공해 입력 보조를 구현할 수 있다. 이를 모델 가중치 학습과 구분해 안내한다. 양식 규칙을 개선할 때는 최고관리자가 승인한 개인정보 없는 예시만 사용한다. 이름만 지우거나 단순 가명으로 바꾼 실제 자료를 익명 자료로 간주하지 않는다.

실제 정보의 일시적인 AI 입력은 모델 학습과 다르지만 외부 개인정보 처리에는 해당할 수 있으므로 아래 전송 조건을 모두 적용한다. 집주소·상세 경력·학력은 업무 단계에서 요구하지 않으면 해당 단계의 전송 필드에서 제외한다. 전송이 필요한 이름·생년월일·연락처 역시 실제 전송 범위에 표시하며, 모든 개인정보가 제거된다고 안내하지 않는다. 직접 추출할 수 있는 값은 내부에서 처리하는 방식을 우선한다.

원본 업무기록의 기존 보관 기준과 AI 임시 입력·응답의 짧은 보관/삭제 기준은 별개이다. 임시 처리물 삭제가 원본·정정 이력의 삭제로 이어지지 않게 한다. 제공업체의 학습 미사용, 임시 보관, 감시 로그, 캐시 및 이미지/파일 예외는 계정·모델·기능별로 확인하며 무보관을 추정하지 않는다.

## 실제 고객 서류 전송 전 필수 조건

1. 최고관리자가 제공업체·모델·처리 목적·데이터 범위·보관 조건을 확인하고 활성화한다. 초기값 OFF. 설정 읽기 실패·미확인 상태에서는 전송하지 않는다.
2. 외부 처리 위탁·국외 이전 해당 여부, 고지 및 적법한 처리 근거를 확인한다. 관리자 승인만으로 고객 개인정보 처리 요건을 충족했다고 판단하지 않는다.
3. OpenAI 계정의 실제 보관 정책과 데이터 공유 설정을 확인한다. 학습 미사용과 무보관을 구분한다. `store:false`만으로 모든 로그·캐시·파일이 무보관이라고 표시하지 않는다. Zero Data Retention은 별도 승인 및 기능별 제약 확인이 필요하다.
4. 원본의 공개 URL 전송을 금지한다. 처리에 필요한 본문·페이지만 서버에서 전송한다. 가능한 경우 자체 텍스트 추출 후 텍스트만 보내고, 필요한 이미지에 한해 사전 확인 후 보낸다. 주민번호·계좌·서명 등 불필요한 영역은 제외한다. 이미지 자동 마스킹을 완전한 보호로 간주하지 않는다.
5. 원본을 보관하는 경우 비공개 저장소, 서버 권한 확인, 짧은 만료의 조회 권한을 적용한다. 원본 보관 정책과 AI 임시 처리물의 삭제 정책을 분리한다. API 파일 저장 기능은 기본 사용하지 않는다. 불가피하게 사용하는 경우 삭제·만료와 삭제 실패 재처리를 검증한다.
6. API 키는 서버 비밀 환경변수에만 둔다. 브라우저·응답·Git·로그로 전달하지 않는다. 요청·응답 원문은 애플리케이션 로그나 분석 도구에 기록하지 않는다. 캐시 및 브라우저 로컬 영구 저장을 금지한다.
7. 직원 권한과 기능 설정을 서버에서 확인하고 전송 전 감사 이벤트를 기록한다. 직원 ID·문서 ID/해시·목적·제공업체·모델·시각·결과 및 반영한 필드를 남긴다. 개인정보 원문을 감사 메타데이터에 복제하지 않는다. 감사 기록 실패 시 전송을 차단한다. 보안 설정 및 접근이력 조회는 기존 최고관리자 권한을 유지한다.
8. 파일 확장자·실제 형식·크기·페이지·압축 해제 한도·암호/매크로·악성 파일 정책을 검증한다. 파일 본문의 지시는 실행하지 않으며 AI에 검색·외부 URL 열기·도구 실행·DB 쓰기 권한을 부여하지 않는다.
9. 허용 필드만 구조화해 수신하고 업무 규칙을 별도로 검증한다. 필드별 근거·미입력·상충 상태를 표시한다. 직원 확인 전 DB에 반영하지 않는다. 기존 값 덮어쓰기와 기등록 후보자 수정은 기존 사유·권한 절차를 따른다.
10. 요청 횟수·파일 크기·시간 제한·사용량 제한과 중복 클릭 차단, 입력/후보자 변경 시 오래된 응답 폐기를 적용한다. 장애 시 추정값이나 성공 표시를 반환하지 않는다.

## 순서

보호 및 제공업체 설정 → 외부 전송 없이 가상 샘플 검증 → API 연결과 전송/이력 검증 → 직원 확인 화면 → 개인정보 조건 충족 확인 → 제한적인 실제 서류 시험.
