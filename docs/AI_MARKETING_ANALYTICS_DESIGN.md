# AI 경영 및 마케팅 분석 설계

2026-11-20 요구사항 반영. 구현 대상은 전년도와 올해의 월별 신규 고객 증가율, 고객 유지율·갱신율, 분야·표준·등급별 추세와 이를 근거로 한 국문 마케팅 요약이다. 계산은 서버의 지표 엔진이 수행하고 AI는 검증된 집계값만 해석한다. 이 문서는 개발 명세이며 기능이나 외부 AI 전송을 활성화하지 않는다.

## 기존 보고서와 확장 범위

현재 `report-analytics.ts`와 월간 업무보고는 고유 후보자 수, 분야·등급·신청 유형별 Job 집계, 청구액·입금액, 접수 기간별 고객의 현재 상태 분포를 제공한다. 정지·철회 발생 이력도 별도 집계한다. 현재 상태 분포는 과거 월말 유지율이 아니다.

새 분석은 기존 표의 의미를 바꾸지 않고 월간 업무보고 안에 별도 분석 구역으로 추가한다. 이전 자료의 시작 시점, 상태·등급 이력, 갱신 대상과 완료 연결을 검증한 지표부터 제공한다. 과거 이력이 없는 항목은 산출 불가로 표시하며 현재 상태로 소급 추정하지 않는다.

## 지표와 집계 기준

### 고객과 신규 고객

고객은 후보자 ID 기준으로 중복을 제거한다. Job 수, 신청 건수, 고유 고객 수를 별도 표시한다. 같은 고객이 여러 표준·등급에 속하면 그룹별 숫자의 합이 전체 고유 고객 수와 다를 수 있다.

| 지표 | 정의 |
| --- | --- |
| 전체 신규 고객 | 전체 유효 신청 이력에서 최초 접수일이 해당 기간에 속하는 후보자 수. 후보자 테이블 생성일이나 신청유형의 최초 표기만으로 판정하지 않음 |
| 표준 신규 고객 | 후보자와 표준의 조합에서 최초 접수일이 해당 기간에 속하는 수. 기존 고객의 새 표준 추가를 포함하며 전체 신규 고객과 구분 |
| 신규 인증 고객 | 최초 인증서 발행일이 해당 기간에 속하는 후보자 수. 접수 기반 신규 고객과 혼용하지 않음 |
| 전년 동월 신규 증감률 | `(올해 신규 고객 수 - 전년도 같은 달 신규 고객 수) / 전년도 같은 달 신규 고객 수 × 100` |
| 고객 순증감 | 동일 범위의 기말 유지 고객 수 - 기초 유지 고객 수. 신규 유입 수와 구분 |

신규 접수 실적에는 취소 확정·오등록 제외 기준을 적용하고 보완 중 신청은 별도 건수로 표시한다. 동일인의 중복 후보자 통합과 접수일 정정은 재집계 버전에 반영한다. 먼저 전체 이력에서 최초일을 결정한 후 분야·표준·등급·파트너 필터를 적용한다. 필터를 먼저 적용해 기존 고객을 전체 신규로 바꾸지 않는다.

자료 이관 전 기간을 포함한 최초 이력이 확인되지 않으면 전체 신규 고객을 확정하지 않는다. 필요하면 별도 지표인 관측 시작 이후 첫 접수로 표시하며 전년 신규 증감률에 대입하지 않는다. 전년도 값이 0이면 증감률은 산출 불가로 두고 이번 기간의 유입 건수만 제시한다.

### 유지율과 갱신율

고객 유지율은 기초 집단을 고정해 계산한다. 전체 고객 기준 기초 유지 집단 S는 기간 시작 직전 ACTIVE 상태의 인증을 하나 이상 보유한 후보자이다. 기말에도 ACTIVE 인증을 하나 이상 보유하는 S의 구성원을 유지 고객으로 세며 새 고객은 분자에 추가하지 않는다.

`고객 유지율 = 기말에도 유지되는 기초 집단 고객 수 / 기초 집단 고객 수 × 100`

분야·표준별 유지율은 같은 범위에서 유지되는 인증을 확인한다. 기존 인증의 갱신·등급변경으로 Job이나 인증서가 대체되면 검증된 선행·후행 연결을 따라간다. 등급별 기초 집단이 상위 등급으로 이동한 경우를 단순 이탈로 세지 않고 등급 이동을 분리한다. 전체 고객 유지율과 특정 등급 잔존율을 다른 지표로 제공한다.

공식 인증상태는 직원이 변경한 이력을 따른다. 만료일이 지났다는 이유로 공식 ACTIVE 상태를 정지·철회로 자동 변경하지 않는다. 유효기간 경과 건수는 별도 보조 지표로 표시한다. 정지 후 복구해 기말 ACTIVE인 경우는 기말 유지에 포함하고 중간 상태 변화는 별도 기록한다. 기초 집단이 0명이면 유지율은 산출 불가다. 80%에서 75%로 변한 경우는 5%p 하락으로 표시한다.

갱신율은 유지율과 별도 계산한다. 분모는 해당 월 만료 예정 인증의 갱신 대상 회차이며, 분자는 정해진 완료 기준일까지 갱신 인증서가 발행되어 선행 인증과 연결된 회차이다. 동일 회차의 재발행·수정본은 중복 계산하지 않는다. 갱신 신청만 한 경우는 진행 중으로 구분한다. 등급변경 등으로 대체된 인증은 별도 대체 사유로 분리하고 임의로 미갱신 처리하지 않는다.

갱신 인정 기간과 유예 일수는 규칙 버전으로 관리한다. 아직 완료 기준일이 지나지 않은 집단은 잠정치로 표시한다. 대상 회차별 비율을 기본으로 하고 후보자 기준 비율은 별도 지표 ID와 분모로 계산한다. 유예 기간, 만료 대상, 완료 연결이 미확정이면 확정 갱신율을 제공하지 않는다.

### 기간과 등급 비교

- 한국 시간 기준으로 날짜를 해석한다. 월간 집계는 월 시작 이상·다음 달 시작 미만으로 정의하고, 상태는 해당 경계 직전의 유효 상태를 복원한다.
- 마감 월은 전년도 같은 달 전체와 비교한다. 진행 월은 양쪽 모두 같은 일자까지로 자르며, 전년도에 없는 일자는 마지막 유효일로 맞춘다. 기준일·잠정 여부를 표시한다. 미래 월은 실적 0이 아닌 미도래로 표시한다.
- 누계 비교는 양쪽 연도 모두 같은 월·일까지만 포함한다. 최근 12개월 이동 합계는 연초 누계와 구분한다.
- 등급 추세는 신규 접수 당시 신청 등급, 인증 발행 당시 승인 등급, 월말 보유 등급을 구분한다. 현재 Job 등급으로 과거 월의 등급을 덮어쓰지 않는다.
- 등급 이동은 같은 표준의 연결된 이전·이후 인증을 사용한다. ISO와 K-Beauty 등급을 같은 서열로 합치지 않으며 등급 순서가 설정되지 않은 분야는 상향·하향 대신 이동 사실만 표시한다.
- 파트너는 해당 접수·인증 당시 연결 정보를 사용한다. 현재 파트너 변경으로 과거 유입 실적을 다시 분류하지 않는다.

### 금액과 마케팅 효과

청구액은 발행월, 실제 입금액은 입금월 기준으로 각각 표시한다. 여러 Job을 묶은 인보이스는 기존처럼 전체 연결 Job을 분모로 한 균등 배분 참고값을 사용하고 배분 방식을 표시한다. 고객 수 변화와 동일 기간 금액을 나란히 보되 이를 회계상 확정 매출이나 이익으로 부르지 않는다. 배분 합계·반올림 차이·누락 연결을 검증하고 비용이 없는 상태에서 수익성을 단정하지 않는다.

유입 경로·캠페인·광고비가 없으면 채널별 전환율, 고객 확보 비용, 광고 수익률은 산출하지 않는다. 이후 유입 경로, 캠페인 코드, 유입일, 문의·신청·발행 단계 및 광고비 기록을 연결해 확장한다. 접점이 여러 개인 고객의 채널 기여 기준은 별도로 정하며 AI가 임의로 배분하지 않는다.

## 필요한 데이터와 품질 상태

| 자료 | 필요한 이력과 검증 |
| --- | --- |
| 후보자와 신청 | 영속 후보자 ID, 유효 접수일, 취소·오등록 사유, 최초 이력의 관측 범위, 후보자 통합 연결 |
| Job과 처리 회차 | 당시 분야·표준·등급·파트너, 신청 유형, 이전·대체 Job/회차 연결 |
| 인증과 상태 변화 | 발행일·만료일, ACTIVE·정지·복구·철회 전환, 실제 적용 시각과 기록 시각, 정정·취소 연결 |
| 갱신 대상 | 선행 인증별 만료 예정일, 제외·대체 사유, 갱신 회차와 후행 인증 연결, 적용한 갱신 기간 규칙 |
| 인보이스와 입금 | 전체 Job 연결, 청구액, 입금액과 발생 시각, 취소·정정·환불 구분 |
| 마케팅 자료 | 후속 확장용 유입 경로·캠페인·광고비·전환 단계 이력 |

상태 복원에는 시작 상태와 전체 전환 이력이 필요하다. 현재 정지·철회 이벤트만으로 복구·갱신 대체까지 복원하지 않는다. 소급 정정은 적용 시각과 기록 시각을 구분하고 보고서 재집계 버전을 만든다. 계획된 미래 상태변경은 적용일까지 실적에서 제외한다.

지표에는 `확정 / 잠정 / 이력 부족 / 조회 실패 / 대상 없음 / 개인정보 보호로 제외 / 미도래` 상태를 둔다. 실패·누락·제외를 숫자 0으로 바꾸지 않는다. 각 지표는 값, 단위, 기간, 분자·분모, 계산 버전, 자료 범위와 품질 상태를 가진다. 부분 조회나 관계 누락은 해당 지표와 이를 인용하는 AI 분석을 차단한다.

## 개인정보 없는 AI 입력

서버는 권한을 확인한 뒤 집계한다. AI 전송용 객체는 허용된 속성만 새로 구성하며 원시 DB 행을 복사한 후 일부 필드를 지우는 방식은 사용하지 않는다.

| 전송 가능 | 전송 금지 |
| --- | --- |
| 지표 ID, 기간, 집계값, 단위, 보호 조건을 통과한 분자·분모, 비교 기준, 품질 상태 | 이름, 생년월일, 전화번호, 이메일, 집주소, 경력·학력, 원문 파일·근거 문장 |
| 분야·표준·등급 코드, 임시 파트너 코드, 보호된 그룹별 집계 | 후보자·Job·신청·인증번호, 내부 후보자 ID, 실제 파트너명, 자유 입력 필터·메모·정지 사유 |
| 산출 불가 항목 코드, 계산 버전, 기준일, 자료 범위 | 개인별 금액, 개인을 추적할 수 있는 행 단위 기록 |

소규모 그룹은 재식별 가능성이 있으므로 최초 구현의 전송 최소 집단 크기는 5명으로 제안한다. 실데이터 전송 전 최고관리자가 확인하며 완전 익명 보장을 뜻하지 않는다. 인원뿐 아니라 분자·분모·금액·변화량으로 작은 집단을 역산할 수 있는지도 함께 검토한다. 전체에서 나머지를 빼 숨긴 값을 알아낼 수 있으면 관련 합계나 다른 그룹도 함께 제외한다. 임의의 세부 필터 반복 요청을 허용하지 않고 승인된 월별 집계 조합으로 제한한다. 내부 화면에 보이는 상세값과 AI에 전송 가능한 값은 분리한다.

AI 전송은 최고관리자의 제공업체·모델·보관 정책 승인과 별도 기능 ON 이후에만 허용한다. 감사 기록 실패·설정 조회 실패·권한 상실 시 전송하지 않는다. API 키는 서버에서만 사용하고 입력·응답 본문을 로그나 분석 도구에 복제하지 않는다. 모델 학습·파인튜닝·평가 데이터 공유를 자동 활성화하지 않는다. 보안 및 추적 기능은 AI 요약 OFF 여부와 무관하게 유지한다.

## AI 분석 결과와 검증

AI의 역할은 확인된 수치 설명, 변화가 집중된 집단 표시, 추가 확인할 가설과 마케팅 실험 제안이다. 고객 증감의 원인을 확정하거나 매출을 보장하지 않는다. 원인 검증 자료가 없으면 확인이 필요한 가설로 분리하고 실제 고객을 접촉하거나 광고를 발송·집행하지 않는다.

국문 결과는 다음 항목으로 구성한다.

1. 핵심 변화: 신규·유지·갱신·등급 추세에서 중요한 변화.
2. 근거: 사용한 지표 ID, 기간, 비교 기준과 시스템 계산값.
3. 검토 가설: 추가로 확인할 자료와 원인 후보.
4. 마케팅 검토 활동: 대상 집단, 제안 활동, 검증 지표와 다음 점검 시점.
5. 분석 한계: 이력 부족·잠정치·작은 집단 제외·광고 자료 미연결 등 해당 결과의 해석에 필요한 조건.

응답은 허용 구조로 받고 모든 관찰에 근거 지표 ID를 요구한다. 존재하지 않는 지표, 제외된 값, 다른 기간, 임의의 숫자 또는 부족한 자료에 대한 원인 단정을 검출하면 결과를 표시하지 않는다. 정형 지표 카드는 원래 시스템 계산값을 사용한다. 조건·기준일·집계값·규칙 버전 변경 시 이전 AI 결과를 만료 처리하고 중복 생성·지연 응답을 차단한다. AI 실패 시 검증된 통계 화면은 유지하고 AI 분석만 실패로 표시한다.

## 화면과 보고서

월간 업무보고의 새 분석 구역에 비교 연도, 기준월·기준일, 분야·표준·등급·파트너 조건을 둔다. 조건 옆에 접수·발행 등 지표별 날짜 기준과 집계 품질을 표시한다. 동일 조건의 비교가 불가능하면 이유를 먼저 보여준다.

- 요약 카드: 신규 고객 수·전년 동월 증감률, 고객 유지율, 갱신율. 비율마다 분자·분모와 잠정 여부 표시.
- 추이: 전년도·올해 월별 신규 고객 비교, 유지율·갱신율 추이, 표준·등급 구성과 이동.
- AI 분석: 명시적으로 누르는 분석 생성 버튼, 결과 기준일, 근거 지표로 이동, 검토 가설과 권장 확인 활동.
- 출력: 같은 집계 스냅샷의 Excel, HTML·PDF용 보고서. AI 해석과 시스템 통계를 구분하고 현재 화면 조건과 버전을 포함.

통계 조회는 기존 보고서 권한을 따른다. AI 생성·요약 열람 권한은 최고관리자가 별도 부여한다. 외부 전송 설정, 소규모 집단 기준, 보관 정책 및 비용 한도 변경은 최고관리자만 수행하며 사유와 이력을 남긴다. AI 분석은 자동 생성·자동 발송하지 않고 최초 구현은 사용자의 명시적 요청으로 생성한다.

## 구현 순서와 완료 조건

| 단계 | 산출물과 완료 조건 |
| --- | --- |
| 1 집계 기반 | 최초 고객 이력 범위·과거 상태·등급·갱신 연결 진단, 부분 조회와 누락 표시. 추가 SQL 및 이관 보강 필요 여부 확정 |
| 2 비교 지표 | 신규·전년 비교·기초 집단 유지·갱신 지표 계산, 등급 이동 분리, 가상 자료의 손계산 결과와 일치 |
| 3 화면과 출력 | 비교 그래프·지표 설명·품질 상태, 같은 조건의 Excel/HTML/PDF 스냅샷 대조 |
| 4 AI 보호와 연결 | 집계 전용 입력, 작은 집단·차분 노출 방지, 권한·감사·OFF 상태 우회 차단, 비용·요청 한도, 가상 자료 API 검증 |
| 5 마케팅 요약 | 근거 지표 연결, 사실·가설·활동 구분, 잘못된 수치·기간 응답 거절, 조건 변경 후 이전 결과 폐기 |
| 6 운영 검증 | 실제 이관 자료·DB 권한·보관 설정 대조 후 제한적으로 활성화. 경력·학력·원문은 분석 입력에 포함하지 않음 |

필수 시험은 동일인의 여러 Job·표준·등급, 필터 전후 최초일, 이관 이전 이력 부족, 전년 0명, 0명 분모, 진행 월·윤년·미래 월, 정지 후 복구, 소급 정정, 대체 인증, 등급 이동, 갱신 기한 전 잠정치, 중복 갱신, 청구·입금 시점 차이, 자료 조회 실패, 개인정보 금지 필드, 소수 집단과 차분 추론, AI 허위 수치·권한 상실·중복 생성·조건 변경을 포함한다.
