# 신규 신청 저장 응답 점검

직원 인증을 확인한 뒤 번호를 예약한다. 신청 생성 RPC가 반환한 신청·후보자·첫 Job ID는 UUID이며, 기등록 후보자 신청이면 선택한 후보자 ID와 일치해야 한다.
담당자와 기존 인증 연결, 추가 Job 전체 입력값, 처리 회차, 관리번호 끝 범위의 저장 응답을 대조한다. 빈 응답이나 일부 행 누락을 성공으로 안내하지 않는다.
연속 클릭은 실행 중인 요청 잠금으로 제한한다. 공유·로컬 모두 저장을 확인한 뒤 화면의 등록 목록과 건수를 갱신한다.

신청 생성 요청 이후 실패하면 일부 저장이 가능하므로 해당 화면의 재등록 버튼을 막는다. 신청관리에서 신청번호로 조회하여 후보자·Job·회차·담당자 연결을 확인한다. 임의 삭제·자동 롤백·예약번호 재사용은 하지 않는다.
화면을 새로 열면 잠금은 초기화되므로 확인 없이 재등록하지 않는다. DB 차원의 영구 중복 방지나 전체 일괄 저장을 구현한 것은 아니다.

현재 신청 생성 RPC는 첫 Job까지 일괄 저장하지만 추가 Job·담당자·관리번호 범위는 별도 요청이다. 완전한 일괄 저장과 복구는 별도 DB 함수/SQL 변경 과제로 남는다. 이번 작업은 기존 DB 구조를 사용하므로 신규 SQL은 없다.
자동검사는 실제 화면 저장 함수를 실행하며 DB 응답은 모의한다. 실제 DB 권한·동시 요청·부분 저장 복구는 별도 검증이 필요하다.
