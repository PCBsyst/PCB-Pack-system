# 개인정보 및 운영 보안 기준

확정일: 2026-10-03 (한국 시간)

이 문서는 사용자가 확정한 요구사항과 현재 저장소의 구현 상태를 구분한다. 요구사항 확정은 운영 환경 적용 완료를 의미하지 않는다. 실서비스의 DB 정책, 인증 설정, 백업 서비스는 별도 검증이 필요하다.

최고관리자 식별은 서버에서 검증되는 계정 ID와 역할로 한다. 이름이나 클라이언트 설정으로 권한을 부여하지 않는다. 최고관리자 계정 ID는 도입 시 확인해야 한다.

초대 → 비밀번호 설정 → 승인 대기 → 최고관리자 활성화 순서로 접근을 허용한다. 비활성화 시 기존 기기의 업무 요청도 차단하고 세션을 종료한다.

## 고객 정보와 이력

원본 개인정보는 보호된 DB에 저장한다. 내부 업무 화면은 마스킹 없이 제공한다. 승인된 모든 활성 직원은 전체 후보자를 조회할 수 있다. 고객 정보와 직원 계정 정보 및 각각의 관리 이력은 구분한다.

고객 정보 변경, 보관, 복원은 사유를 필수 입력한다. 수정자, 서버 시각, 대상 고객, 사유, 변경 전후 값을 보존한다. 이력은 업무 화면에서 수정·삭제할 수 없게 한다. 개인정보 조회와 다운로드는 수행 직원, 시각, 대상, 작업 종류를 별도로 기록하며 최고관리자만 열람한다. 이력에 포함된 개인정보도 보호한다.

보관한 고객은 기본 목록에서 숨기고 보관 목록에서 조회·복원할 수 있다. 신청·Job·인증 이력이 없는 오등록 고객만 최고관리자가 실제 삭제할 수 있다. 삭제 사유·처리자·시각을 남긴다. 업무 기록의 보존기간 경과는 실제 삭제 허용과 별개의 검토 절차다.

보관·복원·개인정보 변경은 인증상태를 바꾸지 않는다. 인증상태는 권한 있는 직원의 명시적 변경으로만 바뀌고 사유와 변경 이력을 남긴다. 유효기간 경과 표시와 저장된 인증상태는 구분한다.

최종 업무 종료일부터 최소 3년 보관한다. 갱신 등으로 업무가 이어지면 관련 기록을 유지한다. 기간 경과 시 자동 삭제하지 않고 최고관리자 삭제 검토 대상으로 표시한다. 한 후보자에 여러 업무가 있을 때 종료일 집계 및 개인정보 삭제 가능 여부는 모든 연결 업무를 기준으로 검증해야 한다.

## 기능 설정

로그인, 접근권한 검사, 개인정보 접근·변경·다운로드 추적, 필수 변경 사유, 이력 보호는 항상 ON이며 해제할 수 없다. 일괄 다운로드, 문서·패키지 생성, 내부 알림, 자료 이관, 향후 Dropbox 자동 보관 등 부가 기능은 최고관리자만 ON/OFF할 수 있다. 서버에서도 실행을 제한하고 변경 사유·시각·전후 설정을 기록한다. 설정을 OFF해도 기존 기록은 삭제하지 않는다.

## 백업과 복구

- 복구 목표(RPO): 최대 15분 이내 데이터 손실. 단순히 설정값을 저장하는 것으로 보장되지 않으며 실제 백업 방식과 복원 시험으로 입증해야 한다.
- 백업 보관기간: 최근 2개월. 고객 업무 기록의 최소 3년 보관과 별개다.
- 권장 방식: 지원 범위에 맞는 지속 변경 보관/PITR과 일별 전체 백업, 서비스 DB와 분리된 암호화 보관.
- 최고관리자만 지원 범위 내 주기·보관기간·복구 목표를 조정하고 변경 이력을 남긴다.
- 실패 시 내부 알림 및 이메일 발송. 최초 실패와 최종 실패 알림, 성공 회복 알림을 제공한다.
- 수신처: jaguen0966@naver.com, info@gpcert.org. 수신처 변경은 최고관리자만 가능하다.
- 최초 실패 후 5분 간격 최대 3회 재시도한다.
- 3개월마다 운영 DB와 분리된 환경에서 복원 검증하고 결과를 기록한다.

Supabase 요금제, PITR 지원·보관 한도, 외부 백업 저장소, 스케줄 실행 환경, 이메일 발송 서비스 및 비용을 확인한 후 구체화한다. 여기의 이메일 예외는 백업 장애·회복 알림이다.

## 로그인과 MFA

모든 사용자에게 1시간 미사용 자동 로그아웃을 적용한다. 종료 전 안내 및 입력값 보존 방법을 마련한다. 최고관리자는 매 로그인 MFA를 요구한다. 직원은 새 기기 또는 15일 신뢰기간 만료 시 MFA를 요구하고, 신뢰기간 내 재로그인 정책은 제공 서비스의 지원 여부를 확인한다.

최고관리자만 직원 신뢰 기기를 해제할 수 있다. 해제 시 해당 기기의 기존 세션을 종료하고 이후 MFA를 요구하며 사유·시각을 기록한다. 직원 MFA 분실은 최고관리자가 본인 확인 후 초기화하고 다음 로그인에서 재등록하도록 한다. 최고관리자의 별도 복구 수단과 서비스 관리자 복구 절차도 마련한다. 복구 코드 및 개별 기기 세션 종료 지원 여부를 확인해야 하며 계정 전체 로그아웃과 구분한다.

## 적용 순서와 이관 전 완료 조건

1. 최고관리자 계정 식별, 역할 분리, 초대 후 승인 대기, 운영 인증 실패 시 차단.
2. 고객 변경 사유 강제, 개인정보 조회·다운로드 기록과 최고관리자 전용 열람.
3. 고객 보관·복원·삭제 제한, 최소 보존기간 및 인증상태 독립성.
4. MFA·신뢰 기기·세션 종료·1시간 미사용 처리·복구 절차.
5. 실제 백업·외부 보관·실패 알림 구축 및 최초 복원 시험.
6. 기능 ON/OFF와 실제 문서 생성 성공 이력 정합성.
7. 가상 후보자 신규 접수부터 저장·새로고침·심의·문서 생성까지 실제 시험하고, 역할별 접근·직접 API·DB 권한·비활성 세션·백업 복원을 검증한다.

빌드·타입 검사 통과는 위 사용자 흐름이나 운영 보안 시험을 대체하지 않는다. 이전 보고에서 샘플 전 과정을 검증했다고 표현했지만, 해당 실행에서는 빌드와 코드 조사만 확인됐다. 새 샘플의 DB 생성부터 최종 다운로드까지 통과했다는 근거는 아직 없다. 실제 개인정보 이관 승인 전 시험 결과와 미해결 항목을 별도 기록한다.
