# 직원 이름 및 로그인 이메일 수정

1. Supabase SQL Editor에서 `supabase/migrations/202610030017_staff_identity.sql`을 실행합니다. 기존 테이블을 다시 생성하지 않으며 재실행 가능합니다.
2. 배포 후 최고관리자의 설정 → 사용자 및 권한 → 직원 이름·이메일 수정 대상에서 직원을 선택합니다.
3. 이름, 이메일, 변경 사유를 입력하고 저장합니다. 이름과 이메일만 변경되며 역할, 승인 상태, 비밀번호, 사용자 UUID는 유지됩니다.

이메일은 서버의 Auth 관리자 API로 확인메일 없이 즉시 변경합니다. 대상 직원과 주소를 확인해야 합니다. 최고관리자 본인의 이메일 변경은 제외합니다. 이미 초대한 승인 대기 계정도 변경 가능하지만 초대메일이 재발송되지는 않습니다.

서비스 키는 서버에서만 사용하며 서버/API 및 SQL 함수 모두 최고관리자 권한을 확인합니다. 프로필과 명시적 변경 이력은 한 DB 트랜잭션으로 저장합니다. Auth와 프로필은 별도 요청이므로 전체가 하나의 트랜잭션은 아닙니다. 프로필 저장 실패 시 Auth 주소를 되돌리고, 복구까지 실패하면 불일치 경고를 표시합니다. 이런 경우 재시도 전에 관리자 점검이 필요합니다.

실서버 검증: 이름 수정 후 새로고침 유지, 이메일 변경 후 새 주소 로그인 및 이전 주소 로그인 실패, 중복 이메일 거부, 사유 누락 거부, 비관리자 API 거부, 이력의 처리자/사유/변경 전후 값 확인. 동시 계정 편집은 피해주세요.
