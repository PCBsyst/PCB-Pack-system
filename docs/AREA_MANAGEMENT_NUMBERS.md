# ISO / K뷰티 관리번호 분리

- 관리 No.는 ISO와 K뷰티 각각 연속 부여합니다. Job No.와 인증번호의 고유성 기준은 변경하지 않습니다.
- 이관 파일에서 같은 분야의 같은 관리번호는 차단합니다. 분야가 다르면 같은 번호를 허용합니다. 앞자리 0은 숫자로 정규화합니다.
- 발행분야 누락·알 수 없는 분야는 등록하지 않습니다. 관리번호 정책 조회 오류도 등록을 차단합니다.
- DB 변경 028 적용 전에는 기존 공통 번호 할당을 유지합니다. 서로 다른 분야의 동일 번호 이관은 028 적용 전 차단합니다.
- 028은 기존 번호를 바꾸지 않습니다. 과거 공통 예약 번호의 최대값을 두 분야에 보수적으로 승계하므로 일부 번호 간격은 남을 수 있습니다. 적용 후 구버전 공통 할당 요청은 거절됩니다.
- 운영 DB에는 아직 적용하지 않았습니다. 023이 선행되어야 하며, 알려진 이관 함수 구조가 다르면 전체 변경을 취소합니다.
- 자동검사 및 빌드는 별도 검증입니다. 실제 DB 동시 등록·RLS·이관 검증 완료를 의미하지 않습니다.

## 2026-10-05 가상 DB 실행 검증

`scripts/test-area-management-db.ps1`은 네트워크·호스트 저장소 연결 없이 임시 PostgreSQL 컨테이너를 생성하고 종료 시 제거합니다. 실데이터와 백업 파일은 읽지 않습니다.

SQL 028을 두 번 실행해 재실행 안전성, 분야별 독립 할당, 공통 예약 최대값 승계, 예약 번호 재사용 방지, 동일 분야 중복 차단, 분야별 이관 식별자, 직접 테이블 접근·익명 함수 실행 제한, 비활성 직원·실무자의 과거 번호 지정 거절을 검사했습니다.

이관 함수는 알려진 번호 블록을 가진 축소 모형입니다. 전체 SQL 023의 후보자 재사용·이력·증빙 흐름, 실제 인증 세션, 동시 요청 검증은 이 검사에 포함되지 않습니다. 운영 DB 적용은 여전히 대기 상태입니다.

## 실제 이관 함수 추가 검증

`scripts/test-area-management-db.ps1 -FullWorkflow`는 최소 테이블 스키마에서 실제 SQL 023과 028을 실행합니다. 검사 중 발견한 신청·처리·인증 상태 CASE 표현식의 enum 변환 누락은 SQL 029에서 보완했습니다. 029도 두 번 적용해 재실행을 확인합니다. 기존 023을 다시 실행하면 보완을 덮어쓰므로 운영 적용은 023 → 028 → 029 순서로 진행해야 합니다.

- 같은 후보자의 ISO/K뷰티 Job 순차 이관 시 후보자 재사용, 개인정보 보완 사유 트리거, 신청·Job·처리 회차·인증 기록 연결 확인
- 정지·철회 상태 및 인증 미발행 상태 유지 확인
- 날짜 누락 실패 시 부분 신청/Job 미생성, 다른 사람의 이메일·보관 후보자 이관 거절 확인
- 증빙 삭제 방지 트리거 실행 확인
- 독립 세션 12개에서 동시에 번호 할당, 분야당 6건 중복 없는 연속 번호 확인

전체 운영 스키마, 실제 직원 인증/RLS, v3 이관 배치 감사 기록, 서로 다른 분야에서 동일 후보자를 **동시에** 이관하는 경우는 아직 미검증입니다. 운영 SQL은 적용하지 않았습니다.

## 동일인 동시 이관 및 배치 감사기록 보완

SQL 030(029 다음 적용)은 기존 기록 이관 요청을 전 분야 공통 트랜잭션 잠금으로 순차 처리합니다. 이는 이관 함수끼리의 후보자 중복 생성을 방지하며 일반 후보자 등록 등 다른 경로까지 잠그는 것은 아닙니다.

배치 이관·실패 기록은 배치 행을 잠근 뒤 RUNNING 상태를 확인합니다. 이미 기록된 행 재이관, 성공 기록의 실패 덮어쓰기, 배치 용량 초과를 차단하고 같은 실패의 반복 요청은 재집계하지 않습니다. 종료 후 추가 이관도 차단합니다. 실패 행의 재처리는 별도의 새 배치를 사용합니다.

가상 DB 검증: SQL 030 재실행, 감사기록의 후보자/신청/Job 연결, 성공·실패 수 집계, 성공 기록 보호, 종료 배치 차단, 실패 배치 승인 거절·성공 배치 승인, 독립 세션 12개의 ISO/K뷰티 동일 후보자 동시 이관(후보자 1명·Job 12개) 확인. 신규 후보자 삽입 지연 트리거로 경쟁 구간을 늘려 검사했습니다.

실제 인증/RLS, 전체 운영 스키마, 배치 종료와 이관의 동시 경쟁, 일반 등록과 이관의 동시 경쟁은 별도 검증 대상입니다. 운영 SQL 028~030은 미적용 상태입니다.
