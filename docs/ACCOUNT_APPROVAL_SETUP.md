# 계정 승인 기반 적용

202610030016_account_approval.sql은 아직 운영 DB에 실행하지 않은 마이그레이션이다.

1. Supabase Authentication > Users와 profiles에서 사용자 본인의 계정 UUID를 확인한다.
2. 사용자 본인이 제공한 UUID 77aa599a-ba14-4cff-99f4-ab8180faaff4가 SQL에 반영돼 있다. 실행 전 대상 프로젝트의 본인 계정인지 대조한다.
3. SQL 전체를 트랜잭션으로 실행한다. 해당 프로필이 없거나 다른 최고관리자가 지정돼 있으면 변경 전체가 롤백된다.
4. is_owner=true인 활성 ADMIN이 정확히 한 명인지 확인한다.
5. 기존 ADMIN은 서브 관리자이며 is_admin()은 최고관리자에게만 true를 반환한다. 기존 관리자용 설정·삭제·이관 정책도 최고관리자 전용이 된다.
6. 새로운 계정은 STAFF, active=false로 생성된다. 최고관리자가 기존 설정의 활성화 버튼으로 승인한다. 기존 활성 직원은 유지된다.

현재 기반에서 아직 남은 작업: 실제 이메일 초대 API, 서브 관리자 초대 화면, 공개 가입 차단, 계정 변경 사유 강제, 세션 토큰 폐기, 계정 권한 시험. is_account_inviter()는 초대 API 권한 검사에 사용할 함수이며 현재 초대 메일을 보내지 않는다.

서버 요청의 active 검사와 RLS는 비활성 계정의 신규 업무 요청을 차단한다. 이미 화면에 표시된 정보 제거와 Auth 세션 자체 회수는 별도 구현해야 한다.

원격 DB 적용 및 역할별 테스트 전에는 전체 계정 관리 구현 완료로 판단하지 않는다. 이번 변경은 타입 검사로 확인하며 원격 SQL 실행·실제 이메일 발송·권한 시험은 수행하지 않았다.
