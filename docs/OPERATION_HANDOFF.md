# 운영 준비 통합 안내 — 2026-10-05

이 문서를 현재 적용 순서와 미완료 작업의 우선 기준으로 사용합니다. 과거 문서의 날짜별 조사 결과는 보존하되 현재 운영 상태로 해석하지 않습니다. 이번 작업에서는 운영 DB를 조회하거나 SQL을 적용하지 않았습니다.

## 지금 확실한 것

- 최근 이관·권한 검사는 실제 SQL을 **격리 가상 DB**에서 실행했습니다. 운영 로그인·API·전체 운영 스키마를 통과했다는 의미는 아닙니다.
- SQL 028~030은 관리번호 분리, 이관 상태 자료형 오류, 동시 이관·배치 감사기록을 보완합니다. 운영 적용 대기입니다.
- SQL 019~027도 저장소 기록상 운영 적용 대기입니다. 그 이후 사용자가 직접 적용했는지는 현재 재확인하지 않았습니다.
- DB에 이미 적용된 SQL 001~018을 처음부터 재실행하지 않습니다. 최신 배포 및 실제 DB 상태를 확인한 뒤 누락분만 적용합니다.
- 자동검사 개수는 코드 검사 결과입니다. 전체 업무 완료율이나 운영 보안 인증으로 환산하지 않습니다.

## 나중에 한 번에 진행할 순서

1. 최고관리자 로그인과 인증 앱의 정상 코드(AAL2), 최신 배포 버전을 확인합니다. 비밀번호·인증코드·설정 키·서비스 키는 대화에 보내지 않습니다.
2. 작업 시간을 정하고 직원 입력/이관을 잠시 중단합니다. 최신 암호화 백업과 격리 복원 결과를 확보합니다. 과거 10월 4일 백업을 현재 백업으로 간주하지 않습니다.
3. [읽기 전용 구조 점검 SQL](../scripts/sql/operational-inventory.sql)을 실행해 필요한 테이블·함수·보호 장치의 존재를 확인합니다. 결과는 적용 이력 인증이 아니라 구조 단서입니다. 오류·예상 밖 구조가 있으면 변경하지 않고 원인을 먼저 확인합니다.
4. 아래 순서대로 누락 SQL을 적용합니다. 각 파일의 성공을 확인하고 오류가 나면 다음 파일로 넘어가지 않습니다. 파일들 전체가 하나의 트랜잭션인 것은 아닙니다.
5. 오래된 페이지를 새로고침하고 가상 DB 등록 샘플로 권한·저장·문서 다운로드를 시험합니다. SQL 적용만으로 합격 처리하지 않습니다.

| 순서 | SQL 번호 / 목적 | 적용 조건 |
| --- | --- | --- |
| 1 | 019 보관·복원 → 020 오등록 삭제 → 021 기능 설정 → 022 패키지 생성기록 → 023 사유·증빙 보호 → 024 동시 수정 | 기존 016 최고관리자 정책 및 관련 감사 트리거 확인. 이 묶음 적용 중 이관 금지 |
| 2 | 025 DB MFA 보호 → 026 최고관리자 MFA ON/OFF | 최고관리자 MFA 등록·AAL2 및 서버 배포 먼저 확인. 기본 MFA ON이며 직원도 인증 수단이 필요함 |
| 3 | 027 이관·테스트 운영 모드 | 026 선행. 운영 모드 OFF/ON과 MFA OFF/ON은 별개 설정 |
| 4 | 028 분야별 관리번호 → 029 이관 상태 변환 → 030 동시 이관·배치 보호 | 023·기존 013 배치 함수 선행. 이관은 세 파일 적용 후 시험 |

파일은 `supabase/migrations/`에 있습니다. 023을 다시 실행하면 뒤의 이관 보완을 덮어쓸 수 있으므로 028 → 029 → 030을 다시 확인해야 합니다. 030은 이관 요청끼리 순차 처리하며 일반 후보자 등록과의 동시 경쟁까지 해결하지는 않습니다.

## 적용 직후 확인

설정의 운영 전 점검은 업무값·인증서·양식·이관 배치 등 10개 테이블의 0행 조회와 MFA/운영 모드 2개 읽기 전용 정책을 확인합니다. 고객 행은 조회하지 않으며 저장·RLS 허용/차단·번호 제약·이관 함수 내용은 인증하지 않습니다. 정책 OFF도 조회 성공으로 표시되므로 상세 상태를 반드시 읽습니다. 설정 화면의 점검 성공만으로 이관을 승인하지 않습니다.

- 최고관리자: 직원 활성화, 접근이력 조회, 사유 필수 기능/MFA 설정. 자기 비활성화 거절.
- 서브관리자: 직원 초대 허용, 활성화·권한 변경·고객 삭제 거절.
- 실무자: 고객 조회·수정·보관·복원 허용, 수정사유·버전 충돌 검사, 고객 삭제 거절.
- 비활성/익명: 업무 데이터 접근과 저장 차단. MFA OFF도 이 제한을 해제하지 않음.
- 샘플 업무: 접수 → 저장/새로고침 → 검토 → 입금 → 심의 → 대표자 승인 → 초안/발행 → 국문·영문 DOCX 및 ZIP 내용·이력 대조.
- 샘플 이관: 같은 분야 번호 중복 거절, 다른 분야 같은 번호 허용, 후보자 재사용·배치 집계·감사기록 확인. 실패 행 재처리는 새 배치로 진행.
- 잘못된 값, 통신 오류, 권한 거절 때 기존 데이터를 덮거나 완료로 표시하지 않는지 확인.

## 실데이터 투입 전 남은 필수 작업

1. 운영 로그인/API/DB의 실제 역할별 시험 및 오래된 비활성 세션 차단 확인.
2. 양식의 필수 항목·국영문·페이지 배치 검수와 공식 PDF 생성 방식 완성. HTML 인쇄는 공식 PDF 완료가 아닙니다.
3. 백업 운영 방식 결정과 실제 반복 실행·실패 알림·다른 기기 복구 검증. 현재 수동 암호화 백업/복원 도구가 있으며 **정기 자동백업·15분 복구 목표·2개월 자동 보관은 보장되지 않습니다**. Storage 실파일·SMTP·환경변수 등은 DB 백업과 별도입니다.
4. 이관 전 번호·동일인·분야/등급·날짜 매핑 검토와 샘플 대조. 일반 등록과 이관의 동시 실행은 검증 전 제한합니다.
5. 기존 구글 시트를 공식 원본으로 병행하고, 대조 오류 해결·백업 복구·권한·업무 테스트 합격 및 최고관리자 승인 후 전환합니다. 실데이터 투입 중 MFA는 ON을 권장합니다.

15일 신뢰 기기, 관리자 복구 절차, 서버 강제 세션 만료는 미완료이며 구현 또는 운영 대체 절차를 확정해야 합니다. Dropbox 자동 보관은 요청대로 후순위입니다. 과거 시점별 월말 상태 통계와 Word/PDF 외 PPT/Excel 산출물의 지원 범위도 별도로 확인합니다.

## 직접 필요한 작업과 자동 진행 가능한 작업

월간 고객 상세 CSV는 서버 재조회 후 신청별 개인정보 접근이력 저장에 성공해야 응답합니다. 기존 접근이력 RPC(SQL 018)와 서버 서비스 키가 필요하며 새 SQL은 없습니다. 요청당 신청 100건·Job 5,000건·파일 20MB로 제한하고 전체 신청 조회가 10,000건을 넘으면 중단합니다. 접근이력은 응답 준비 기록으로, 실패 시 일부 기록이 남을 수 있고 PC 저장 완료를 보장하지 않습니다. 집계 CSV·인쇄는 이 서버 기록 경로를 사용하지 않습니다. 운영 DB 권한·실제 다운로드는 별도 검증 대상입니다.

사용자 직접: 인증코드 입력, 공급자 로그인·승인, 비밀정보의 안전한 로컬 입력, 실무 검수·실데이터 대조 및 최종 전환 승인. 지금 즉시 요청하지 않습니다.

자동 진행 가능: 코드 보완, 가상 DB 검사, 문서/이관 검증 도구, 배포 및 결과 정리. 운영 보안 변경·실데이터 이관은 준비됐다는 이유만으로 자동 실행하지 않습니다.
