# 운영 준비 통합 안내 — 2026-10-05

이 문서를 현재 적용 순서와 미완료 작업의 우선 기준으로 사용합니다. 과거 문서의 날짜별 조사 결과는 보존하되 현재 운영 상태로 해석하지 않습니다. 이번 작업에서는 운영 DB를 조회하거나 SQL을 적용하지 않았습니다.

## 지금 확실한 것

- 패키지 다운로드와 업무 단계 완료는 구분합니다. 패키지 준비 단계에서 시작했고 수신 시 같은 단계·편집 권한·전체 문서 생성이 확인된 경우에만 완료로 전환합니다. 공유 DB 신청은 RECORDED 생성기록도 필요합니다. 이전 단계의 확인용 다운로드는 단계가 바뀌지 않고, 완료 상태에서 일부 문서를 다운로드해도 업무 단계를 역행시키지 않습니다. 다운로드 기록은 보존하되 단계 공유 저장/PC 실제 저장 완료/서버 차원의 업무 단계 강제는 별도 확인 대상입니다.

- 단계 확정 작업은 현재 업무 단계에서만 실행합니다. 검토→청구→입금→심의→초안→전자본→송부 순서의 다른 단계 확정은 저장 요청 전 거절하고, 완료 후 재확정으로 단계가 역행하는 것을 차단합니다. 승인 Job이 없으면 초안 확정을 거절합니다. 기존 탭의 조회/입력 및 자료 다운로드는 이 제한으로 잠그지 않습니다. 정정/재심의/반려 후 재개를 위한 별도 명시적 전환과 서버 단계/RLS 강제는 구현 완료로 보지 않습니다.

- 심의 재처리의 기존 회차/위원 명단 대조는 본문 저장 전에도 실행합니다. 사전 조회 실패·다른 위원 명단·조회 중 입력/편집 상태 변경은 본문 저장 전 중단합니다. 심의·송부는 로그인 사용자 ID 또는 인증 응답을 확인하지 못하면 담당자 없는 기록을 저장하지 않습니다. 저장 후 응답 대조도 유지합니다. 사전 확인 후 다른 기기가 변경할 가능성, 전체 저장의 원자성, 실제 서버 권한/운영 DB 검증은 별도입니다.

- 발행 재처리는 회차의 기존 인증정보를 먼저 조회하고 번호·날짜·Rev·상태가 일치하는지 대조합니다. 신규 회차만 INSERT하며 기발행 인증정보는 UPDATE/UPSERT하지 않습니다. 기발행 Job도 활성 상태를 조회로 확인하고 상태를 덮어쓰지 않습니다. 기존 정보가 다르거나 정지/철회/대체된 경우 진행을 중단합니다. 신규 인증 저장 뒤 Job 상태 저장이 실패한 경우의 재처리는 이 보호로 중단될 수 있으므로 별도 복구가 필요합니다. 클라이언트의 재처리 보호이며 직접 DB 수정 방지나 전체 저장의 원자성을 보장하는 서버 제약은 아닙니다.

- 인증서 발행은 저장된 Job·회차·인증번호·Rev·초안/발행/만료일·상태·대체 이력을 입력값과 대조한 뒤 기존 인증 상태 변경과 다음 단계로 진행합니다. 기존 Job의 현재 인증기록이 중복되면 발행 기록을 중단합니다. 송부도 회차·문서전달 항목·전자본/원본 날짜·운송장·담당자·비고를 대조한 뒤 진행합니다. 실제 존재하지 않는 날짜와 발행일보다 빠른 만료일을 차단하며 JSON 객체의 키 순서 차이는 무시합니다. 저장 성공 후 후속 회차/상태 저장 실패 시 앞선 기록이 남을 수 있습니다. 자동 롤백·기발행 정보 불변에 대한 서버 강제·운영 DB/권한별 검증은 별도입니다.

- 심의 단계는 Job별 결과·의견·심의일·대표자 승인정보와 모든 선택 위원의 대상·결정·의견을 저장 응답과 대조합니다. 중복 위원 ID/회차를 거절하고 현재 선택에 없는 이전 위원 기록이 보이면 자동 삭제하지 않고 진행을 중단합니다. 이 경우 앞선 심의 본문 저장은 이미 완료됐을 수 있습니다. 전체 심의 저장의 트랜잭션/자동 롤백이나 다른 기기의 동시 수정을 보장하지 않으며 실제 운영 DB/권한별 검수는 별도입니다.

- 최근 이관·권한 검사는 실제 SQL을 **격리 가상 DB**에서 실행했습니다. 운영 로그인·API·전체 운영 스키마를 통과했다는 의미는 아닙니다.
- SQL 028~030은 관리번호 분리, 이관 상태 자료형 오류, 동시 이관·배치 감사기록을 보완합니다. 운영 적용 대기입니다.
- SQL 031은 서버에 없는 로그아웃 세션과 기한이 지난 세션의 업무 접근을 차단합니다. 준비·격리 DB 검증 단계이며 운영 적용 대기입니다. 1시간 미사용 강제 만료 자체를 구현한 것은 아닙니다.
- SQL 019~027도 저장소 기록상 운영 적용 대기입니다. 그 이후 사용자가 직접 적용했는지는 현재 재확인하지 않았습니다.
- DB에 이미 적용된 SQL 001~018을 처음부터 재실행하지 않습니다. 최신 배포 및 실제 DB 상태를 확인한 뒤 누락분만 적용합니다.
- 자동검사 개수는 코드 검사 결과입니다. 전체 업무 완료율이나 운영 보안 인증으로 환산하지 않습니다.

2. 작업 시간을 정하고 직원 입력/이관을 잠시 중단합니다. 최신 암호화 백업과 격리 복원 결과를 확보합니다. 과거 10월 4일 백업을 현재 백업으로 간주하지 않습니다.

## 적용 직후 확인

설정의 운영 전 점검은 업무값·인증서·양식·이관 배치 등 10개 테이블의 0행 조회와 MFA/운영 모드/현재 세션/미사용 기한 4개 읽기 전용 검사를 확인합니다. 고객 행은 조회하지 않으며 저장·RLS 허용/차단·번호 제약·이관 함수 내용은 인증하지 않습니다. 정책 OFF도 조회 성공으로 표시되므로 상세 상태를 반드시 읽습니다. 설정 화면의 점검 성공만으로 이관을 승인하지 않습니다.

- 최고관리자: 직원 활성화, 접근이력 조회, 사유 필수 기능/MFA 설정. 자기 비활성화 거절.
- 서브관리자: 직원 초대 허용, 활성화·권한 변경·고객 삭제 거절.
- 실무자: 고객 조회·수정·보관·복원 허용, 수정사유·버전 충돌 검사, 고객 삭제 거절.
- 비활성/익명: 업무 데이터 접근과 저장 차단. MFA OFF도 이 제한을 해제하지 않음.
- 샘플 업무: 접수 → 저장/새로고침 → 검토 → 입금 → 심의 → 대표자 승인 → 초안/발행 → 국문·영문 DOCX 및 ZIP 내용·이력 대조.
- 샘플 이관: 같은 분야 번호 중복 거절, 다른 분야 같은 번호 허용, 후보자 재사용·배치 집계·감사기록 확인. 실패 행 재처리는 새 배치로 진행.
- 잘못된 값, 통신 오류, 권한 거절 때 기존 데이터를 덮거나 완료로 표시하지 않는지 확인.

## 실데이터 투입 전 남은 필수 작업

1. 운영 로그인/API/DB의 실제 역할별 시험 및 오래된 비활성 세션 차단 확인.
2. 양식의 필수 항목·국영문·페이지 배치 검수와 공식 PDF 생성 방식 완성. HTML 인쇄는 공식 PDF 완료가 아닙니다.
3. 백업 운영 방식 결정과 실제 반복 실행·실패 알림·다른 기기 복구 검증. 현재 수동 암호화 백업/복원 도구가 있으며 **정기 자동백업·15분 복구 목표·2개월 자동 보관은 보장되지 않습니다**. Storage 실파일·SMTP·환경변수 등은 DB 백업과 별도입니다.
4. 이관 전 번호·동일인·분야/등급·날짜 매핑 검토와 샘플 대조. 일반 등록과 이관의 동시 실행은 검증 전 제한합니다.
5. 기존 구글 시트를 공식 원본으로 병행하고, 대조 오류 해결·백업 복구·권한·업무 테스트 합격 및 최고관리자 승인 후 전환합니다. 실데이터 투입 중 MFA는 ON을 권장합니다.

15일 신뢰 기기, 관리자 복구 절차, 서버 강제 세션 만료는 미완료이며 구현 또는 운영 대체 절차를 확정해야 합니다. Dropbox 자동 보관은 요청대로 후순위입니다. 과거 시점별 월말 상태 통계와 Word/PDF 외 PPT/Excel 산출물의 지원 범위도 별도로 확인합니다.

서버 1시간 미사용 차단은 SQL 032와 화면/API 코드를 준비하고 격리 DB에서 검증한 상태로 운영 적용 대기입니다. 서버가 확인한 마지막 활동부터 1시간이 지나면 기존 권한 함수·RLS·화면/API가 거절합니다. 기록이 없는 세션은 auth.sessions.created_at을 시작점으로 사용하며 새로고침·일반 조회·JWT 갱신으로 시간을 연장하지 않습니다. 실제 입력 시 활동 POST를 30초 간격으로 보내므로 만료 기준은 마지막 입력의 정확한 시각이 아닌 마지막 서버 확인 시각입니다. GET과 재점검은 읽기만 수행합니다. 서버 응답이 불확실하면 화면을 숨기고 입력 컴포넌트는 유지하며, 만료 확정 시 재로그인합니다. 다른 기기는 서로 다른 세션으로 관리합니다. 브라우저 시계·로컬 저장값은 서버 권한 판정에 사용하지 않습니다. 활동 호출은 사용자 인증을 검증하지만 사람이 실제로 조작했는지 증명하는 기능은 아닙니다.

032 미적용이면 화면에 적용 대기를 표시하고 기존 브라우저 타이머만 유지합니다. 026·031 재실행은 연결을 덮어쓸 수 있으므로 032를 다시 확인합니다. MFA OFF도 서버 미사용 제한을 해제하지 않습니다. 실제 Supabase 로그인·여러 탭·절전 복귀·기기 시계 변경·네트워크 단절 후 재시도 검증과 주기적 활동 테이블 정리는 별도 운영 검증 대상입니다. auth 테이블이나 토큰은 변경하지 않습니다.

031 적용 후에는 JWT의 session_id와 auth.sessions의 사용자·기한 및 활성 직원 상태를 대조합니다. 로그아웃으로 제거된 세션의 남은 JWT도 화면/API/기존 RLS 권한 함수에서 거절합니다. 정책 조회 장애는 접근 허용으로 바꾸지 않습니다. 함수 미등록(PGRST202이며 해당 함수명 일치)만 이전 직원/MFA 검사로 유지하며 운영 점검에 적용 필요를 표시합니다. 026을 다시 실행하면 연결 함수가 덮어써지므로 031을 다시 확인해야 합니다. auth 테이블·토큰을 수정하거나 세션 ID를 화면/로그에 노출하지 않습니다. 이미 시작된 요청의 중간 취소 및 실제 인증 서비스 세션 삭제·운영 DB 권한 드리프트는 별도 검증 대상입니다.

## 직접 필요한 작업과 자동 진행 가능한 작업

월간 고객 상세 CSV는 서버 재조회 후 신청별 개인정보 접근이력 저장에 성공해야 응답합니다. 기존 접근이력 RPC(SQL 018)와 서버 서비스 키가 필요하며 새 SQL은 없습니다. 요청당 신청 100건·Job 5,000건·파일 20MB로 제한하고 전체 신청 조회가 10,000건을 넘으면 중단합니다. 접근이력은 응답 준비 기록으로, 실패 시 일부 기록이 남을 수 있고 PC 저장 완료를 보장하지 않습니다. 집계 CSV·인쇄는 이 서버 기록 경로를 사용하지 않습니다. 운영 DB 권한·실제 다운로드는 별도 검증 대상입니다.

사용자 직접: 인증코드 입력, 공급자 로그인·승인, 비밀정보의 안전한 로컬 입력, 실무 검수·실데이터 대조 및 최종 전환 승인. 지금 즉시 요청하지 않습니다.

문서 수신은 선언된 크기와 실제 스트림 바이트를 대조하며 Word 25MB, 상세 CSV 20MB, ZIP 100MB로 제한합니다. 초과·잘림·해시 불일치 시 브라우저 저장 및 화면의 패키지 완료 이벤트를 중단합니다. ZIP은 MIME·크기·SHA-256 모두 필수이며 서버도 100MB 초과 출력은 생성이력 기록 전에 거절합니다. 이는 수신 무결성 검사이지 Word 페이지 배치 검증, 악성 파일 검사 또는 PC 저장 완료 증명은 아닙니다. 다운로드 이전 서버 응답 준비 이력은 남을 수 있습니다. 새 ZIP 크기 헤더가 없는 구형 배포 응답은 저장하지 않으므로 배포 후 오래 열린 화면은 새로고침합니다. 추가 SQL이나 설치는 필요 없습니다.

자동 진행 가능: 코드 보완, 가상 DB 검사, 문서/이관 검증 도구, 배포 및 결과 정리. 운영 보안 변경·실데이터 이관은 준비됐다는 이유만으로 자동 실행하지 않습니다.

신청 상세의 정식 검토·청구·입금·심의·발행·송부 확정은 같은 화면에서 한 번에 하나만 실행하며 저장 중 입력을 잠시 잠급니다. 저장 중 입력 변경/화면 종료/편집 권한 상실 시 다음 단계 이동을 막습니다. 검토·심의 회차 날짜, 발행/송부 회차, 기존 인증 대체 상태와 Job 인증상태의 UPDATE 응답 ID를 예상 범위와 대조하고, 입금은 수정된 인보이스 1건이 있어야 진행합니다. 청구/입금액은 유한한 양수 및 소수점 이하 2자리까지 허용합니다. 여러 요청을 DB 트랜잭션으로 묶지는 않았으므로 중간 실패 시 앞선 정식 기록은 남을 수 있습니다. 자동 롤백·다른 탭/기기의 중복 실행·인보이스 번호의 소유 관계·서버 원자적 확정은 별도 보완 대상입니다. 입력 잠금과 단일 실행은 보안 권한/RLS 검사를 대체하지 않습니다. 실제 운영 역할별 저장 응답/RLS 검수는 별도입니다.

상태변동 Excel은 조회 조건과 기간별 정지·철회 고객 수/처리 건수 2개 시트를 제공합니다. 상태 적용일 기준이며 미래 적용일 기록도 포함하고, 같은 후보자의 여러 Job·반복 처리를 고객 수와 구분합니다. 과거 월말 유지 상태나 전체 상태 이력을 복원하는 기능은 아닙니다. 고객 원문은 제외되지만 조회 조건은 포함됩니다. 조회 실패·생성 중 조건 변경·화면 종료 시 저장하지 않습니다. 수익 조회는 연결 Job ID가 없거나 잘못된 인보이스도 오류로 처리하며 0원으로 대체하지 않습니다. 추가 설치·SQL은 없고 실제 Excel 앱 시각 검수·운영 DB 대조는 별도입니다.

월간 신청·수익·정지/철회 화면 조회는 각 페이지의 정확 행 수(count exact)와 최종 고유 ID 수를 대조합니다. 행 수 누락/변경·부분 조회·페이지 500행 초과·테이블별 10,000행 초과이면 결과를 완료 집계로 표시하지 않습니다. 수익·변동 실패는 0건/0원으로 치환하지 않습니다. 전체 조회 한도는 현재 클라이언트 방식의 운영 한계이며 더 큰 원장은 서버 측 기간/분야 집계로 전환해야 합니다. 이 검사는 동일 개수 내 값 변경이나 ID가 유지된 수정까지 검출하지 않으며 여러 페이지의 트랜잭션 스냅샷을 보장하지 않습니다. 각 테이블의 독립 조회도 동일 시점 자료는 아닙니다. 추가 SQL은 없습니다.

월간 업무보고의 집계 Excel(.xlsx)은 현재 화면 조회 자료를 기준으로 조회 조건·전체 요약·표준별·등급별·유형별 5개 시트를 생성합니다. 숫자는 숫자 셀이며 문자열은 수식이 아닌 텍스트로 기록합니다. 후보자명·연락처·Job/인증번호 원문은 제외되지만 파트너사 등 필터 조건은 포함됩니다. 고객 수가 아닌 Job 수, 조회 당시 현재 상태 기준이며 과거 월말 상태나 해당 월 신규 발행 건수로 해석하지 않습니다. 수익·고객 상세·서버 접근이력은 이 내보내기 범위 밖입니다. 새 설치·SQL 없이 기존 ZIP 라이브러리를 필요 시 로딩합니다. OOXML 구조·합계 검사는 완료했고 실제 Excel 앱의 열림/인쇄/시각 검수는 별도입니다.

2026-10-06 고객·수익 분석 영역에는 별도 Excel 내보내기를 연결했습니다. 선택한 집계 구분의 고객/Job 수·청구액·입금액 및 월/연 고객 추이를 조회 조건·고객 및 수익·고객 추이 3개 시트로 저장합니다. 청구는 발행월, 입금은 실제 입금월이며 전체 연결 Job에 균등배분한 참고값입니다. 화면과 같이 집계 행별 원 단위 반올림을 적용해 분할 행의 반올림 합계는 원본 금액과 다를 수 있습니다. 수익 조회 미확인/실패 상태에서는 내보내기를 차단하며 금액을 0원으로 대체하지 않습니다. 고객 상세·인보이스 번호는 제외되지만 조회 조건은 포함됩니다. 서버 접근이력과 저장 완료 기록은 남기지 않습니다. 실제 Excel 앱·운영 DB 대조는 별도 검수 대상이며 추가 SQL·설치는 없습니다.

# 인보이스 저장 보호 추가

패키지 목록의 문서 이력은 현재 조회된 Job을 100개씩 묶고 문서를 ID 순서로 500건씩 조회합니다. 전체 이력 10,000건까지 허용하며 중복 ID·잘린 응답·페이지 간 전체 건수 변경·Job 범위 오류가 발견되면 부분 결과를 표시하지 않습니다. 화면 종료 또는 재조회 시 이전 요청의 후속 페이지 조회를 중단합니다. 이는 현재 목록에 로드된 Job 범위에만 적용되며 고정 DB 스냅샷이나 신청 원장 전체 조회를 보장하지 않습니다. 이전의 기본 문서 조회 한도는 이 범위에서 해소했습니다.

패키지 목록의 기존 문서 이력은 Job 범위·언어·형식·날짜·응답 행 수를 검증합니다. 조회 실패 또는 잘린 응답이면 언어 표시를 `기존 이력 조회 미확인`으로 구분하고, 정상 조회의 빈 결과는 `확인된 기존 언어 이력 없음`으로 표시합니다. 현재 생성 응답이 확인된 경우에는 그 언어를 별도로 표시할 수 있습니다. 기존 ZIP 형식과 별도 문서 종류는 허용하며 문서 이력 행은 실파일 존재의 증거가 아닙니다. 실제 DB의 기본 조회 한도를 넘으면 전체 자료를 페이지로 가져오는 추가 구현 전까지 조회 미확인으로 안내합니다.

패키지 생성 이력 조회 시 문서 수·양식 구성·언어·중복·날짜·ZIP 검증값의 구조를 대조합니다. 확인되지 않는 응답은 정상 이력으로 표시하지 않으며 DB 기록을 수정하거나 삭제하지 않습니다. 양식 개정정보가 없는 이전 기록은 허용합니다. 재조회 시작 시 이전 기록과 직원명 표시를 비우고 늦은 응답 및 화면 종료 후 응답은 무시합니다. 이는 메타데이터 검증이며 ZIP 파일 자체의 무결성 또는 현재 입력과의 일치를 보증하지 않습니다.

패키지 화면에 생성 언어 및 양식별 영문 의견 사전 점검을 추가했습니다. 국문만 선택하면 번역 점검은 적용하지 않고, 영문 선택 시 기존 문서 생성 API와 동일한 번역 검사 함수를 사용하여 Job별 서류검토서·인증결정보고서·문서전달확인서의 입력 누락을 안내합니다. 선택되지 않은 위원과 국문 의견이 없는 항목의 번역은 요구하지 않습니다. 누락 안내에서 영문 입력 영역으로 이동할 수 있습니다. 번역 입력 여부만 확인하며 번역 정확성·양식 준비·공유 저장 성공·생성 권한을 보증하지 않습니다.

정정 처리 함수에 대한 모의 실행 검사도 추가했습니다. 만료일이 전자본 발행일보다 앞서는 경우, 잘못된 날짜/검토결과, 빈 사유/500자 초과/제어문자, 인증 실패, 화면 종료, 편집권한 상실 및 저장 중 입력 변경을 검사합니다. 공유 모드 정정 이력에는 직원 표시명과 계정 ID를 함께 기록하며 표시명 조회 실패 시 정정을 중단합니다. 이 검사는 운영 DB 또는 실제 브라우저 검증을 대체하지 않습니다.

업무 입력 정정은 현재 워크스페이스와 패키지용 입력만 변경합니다. 정식 검토·청구·입금·심의·인증 테이블의 원문을 수정하지 않습니다. 인증번호 정정의 필드 연결을 수정했으며 인증서 발행일과 알 수 없는 인증 필드는 정정 대상에서 제외합니다. 날짜와 검토결과를 검증하고 공유 모드에서는 로그인 사용자의 ID를 정정 이력에 기록합니다. 정정 후 이전 패키지 생성 표시는 해제됩니다. 공유 저장 성공과 실제 DB 정정 절차는 별도 확인이 필요합니다. 모바일·태블릿 대응은 사용자 요청에 따라 보류합니다.

연결 저장 실패 후에는 청구·입금 대기 화면의 `기존 미입금 인보이스의 Job 연결 복구`를 사용할 수 있습니다. 금액·발행일·수신자 정보가 일치하고 입금 기록이 없는 경우에만 허용하며, 다른 신청의 Job 또는 현재 Job의 다른 청구 연결을 발견하면 거절합니다. 복구 확인과 1~500자 사유 입력을 요구하고 성공한 복구 사유를 현재 업무기록의 처리 이력에 남깁니다. 신규 발행·복구 모두 응답의 인보이스 ID와 전체 Job ID를 대조합니다. 신규 발행 전 기존 Job 청구 연결도 확인합니다. 인보이스 원문 수정·삭제는 수행하지 않습니다. 복수 조회/저장 사이의 동시 변경, RLS로 가려진 연결, 실패한 요청의 독립 서버 감사기록 및 DB 원자적 복구는 보장하지 않습니다. 실제 운영 DB/권한별 검수는 별도입니다.

신청 상세에서는 기존 인보이스 번호의 청구·입금 정보를 덮어쓰지 않고 신규 INSERT만 수행합니다. 입금 확인 전 저장된 청구금액과 현재 신청의 모든 Job 연결을 대조하며, 여러 후보자를 포함하는 통합 인보이스 연결은 허용합니다. UPDATE는 조회한 ID·미입금 상태·조회 당시 금액을 조건으로 실행하여 상태나 금액이 변경되면 다음 단계로 진행하지 않습니다. 연결 실패 후 남은 신규 인보이스의 재연결、기존 청구 수정은 별도 보완 대상입니다. 이 검사는 클라이언트 업무 보호이며 서버 권한/RLS나 여러 테이블의 원자적 처리를 대체하지 않습니다.

이미 입금된 통합 인보이스는 각 연결 신청의 청구·입금 대기 화면에서 `기존 통합 입금 확인 후 심의로 진행` 버튼으로 반영할 수 있습니다. 저장된 전액 입금·유효한 날짜·원 확인 담당자·현재 신청의 모든 Job 연결을 확인하고, 청구 및 입금 정보를 현재 업무기록에 반영합니다. 인보이스와 연결 테이블은 읽기만 하며 다른 신청을 일괄 수정하거나 새 입금으로 집계하지 않습니다. 현재 업무기록의 새로고침 후 보존은 기존 업무 저장 큐의 성공 여부에 따릅니다. 여러 조회 사이의 DB 변경을 고정 스냅샷으로 보장하지 않으며 운영 DB/역할별 검증은 별도입니다.
