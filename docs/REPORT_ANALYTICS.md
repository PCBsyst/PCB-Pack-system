# 고객 및 수익 분석

## 현재 제공 기능

보고서 상단 공통 조회 조건에 등급·신청유형을 추가했다. 월간 상세/인쇄/CSV와 고객·수익·현재 상태·실제 상태변동 분석이 동일한 분야·표준·파트너·등급·유형 조건을 사용한다. 날짜는 각 지표의 접수일/발행일/입금일/상태 적용일 기준을 유지한다.

추가: certification_actions의 effective_date를 기준으로 실제 정지·철회 월/연 변동을 별도 표시한다. 고유 고객 수와 처리 건수를 구분하며 같은 이벤트 ID는 중복 제거한다. 조회 실패는 0건으로 표시하지 않는다. 미래 적용일도 그 기간에 포함하므로 완료 실적과 동일하지 않다. 기존 010 상태변동 테이블을 사용하며 신규 SQL은 없다. 복구/갱신 대체 전체 이력이나 과거 월말 유지 고객 수 복원은 여전히 미구현이다.

월간 업무보고의 분야·등급·신청 유형별 집계와 선택 연도 월별/최근 5년 연별 고객 추이를 제공한다. 표준·파트너 필터를 함께 적용한다. 후보자 ID별 고객 중복을 제거하지만 여러 분야나 상태에 속한 고객은 각 그룹에 포함되므로 행 합산값은 전체 고유 고객 수와 다를 수 있다.

청구액은 인보이스 발행일, 실제 입금액은 paid_at/paid_amount 기준이다. 현재 DB에 통합 인보이스의 Job별 상세 금액이 없으므로 전체 연결 Job 수로 균등 배분한다. 필터를 적용해도 분모를 줄이지 않는다. KRW 운영 기준의 참고 분석이며 회계상 매출 확정이나 세금 계산을 대체하지 않는다. 수익 조회 실패/미연결은 미확인으로 표시한다.

고객 추이는 접수 시기별 고객의 현재 상태 분포이다. 과거 월말/연말 유지 고객의 실제 상태 복원은 아직 제공하지 않는다. 정지/철회/복구/갱신 대체의 전체 이벤트 모델을 확보하고 검증한 후 구현해야 한다. 일반 인증 만료를 자동 정지 처리하지 않는다.

분석 결과는 별도 CSV로 내려받는다. 문서/CSV는 다크 UI와 무관하게 기존 출력 형식을 유지한다. 신규 SQL 불필요. 실 DB 데이터와 인보이스 연결 누락·부분 입금·상태이력의 운영 검증은 별도 필요하다.

## 전년 비교와 AI 마케팅 분석 개발 범위

### 자료 준비 상태와 월별 관측 비교

2026-11-20 월간 업무보고에 신규 고객 비교와 자료 준비 상태 구역을 연결했다. 서버 API `/api/reports/customer-acquisition`가 신청과 Job을 각각 분할 재조회하고 관계·건수·날짜를 확인한다. 후보자 이름·생년월일·연락처는 조회하지 않으며 브라우저에는 고객 ID나 행 단위 이력 없이 집계만 반환한다. 기존 상세 보고서의 신청별 문서 응답 이력과는 별개인 내부 집계 조회다. 외부 AI 호출은 없다.

Job 없는 첫 신청도 전체 관측 고객 수에 포함한다. 전체 이력에서 후보자별 최초일과 후보자·분야·표준 조합의 최초일을 먼저 구하고 분야·표준·파트너 필터를 적용한다. 같은 날 여러 표준을 처음 신청한 경우는 기존 고객의 후속 추가로 세지 않는다. 취소 접수는 제외하며 미래 접수는 실적에 포함하지 않는다. 전체 신청/Job 수, Job 없는 신청, 취소·미래 접수, 유효 접수 관측 범위를 표시한다.

비교는 접수 기준이다. 상단 월은 비교 연도 선택에 사용하고 등급·유형·현재 상태·인증발행일 필터는 적용하지 않는다고 표시한다. 진행 월은 전년도 같은 날짜까지 비교하고 윤년은 유효한 마지막 날짜로 맞춘다. 미래 월은 미도래로 둔다. 과거 이력이 완전하다는 승인 근거가 아직 없으므로 실제 신규 고객 수·신규 증감률·유지율·갱신율은 항상 산출 보류이며 관측 첫접수 숫자를 이 지표로 대체하지 않는다. 브라우저 요청으로 이력 확인 상태를 변경할 수 없다.

월별 막대 비교와 집계 CSV를 제공한다. CSV에도 관측 기준, 비교 종료일, 산출 보류를 유지한다. 개발용 가상 예제는 별도로 선택하며 DB와 섞거나 저장하지 않는다. 실패·부분 조회·손상 응답은 0건으로 표시하지 않고, 조건 변경 시 이전 결과와 늦게 도착한 응답을 폐기한다. 개별 페이지 조회 검증은 트랜잭션 시점의 완전한 스냅샷 보장을 뜻하지 않는다. API는 직원 권한·세션·MFA 검사를 적용하고 캐시를 금지한다. 신규 SQL은 필요하지 않다.

### 유지 및 갱신 이력 점검

2026-11-20 신규 고객 비교 아래에 유지·갱신 이력 준비 상태를 연결했다. `/api/reports/certification-lifecycle`가 신청·Job·처리 회차·인증 기록·상태변경을 각각 분할 조회한다. 이름·연락처·인증번호·정지 사유는 조회하지 않고 식별자는 서버 연결 검사에만 사용한다. 응답과 CSV는 집계값만 포함한다.

월별로 전년도·올해의 기록된 유효기간 종료 건수와 갱신 발행 건수를 비교하며, 올해 이전인증 연결 확인·등급변경 발행·정지·철회 적용 건수도 표시한다. 오류 연결 기록과 미래 발행/적용 기록은 해당 실적에서 제외한다. 만료 기록에는 대체된 과거 인증도 포함되므로 확정 갱신 대상 분모로 사용하지 않는다. 발행·만료·상태 적용일을 구분하고 진행 월은 같은 날짜까지 비교한다.

이전 Job과 인증은 같은 후보자·분야·표준, 인증·회차 소속, 발행 순서, 대체된 원본의 이력 상태를 확인한다. 자기참조·순환·여러 후행 인증 연결·복수 현재 인증·이전 연결 미확인·상태변경 연결 오류를 유형별 집계한다. 진단은 전체 조회 범위이고 월별 표는 선택한 분야·표준·파트너 범위이다. 오류 유형의 합을 고유 오류 기록 수로 표시하지 않는다. 전체 조회 성공이나 오류 0건이 이관 이전 이력의 완전성을 증명하지는 않는다.

유효기간이 지났지만 현재 ACTIVE인 기록은 별도로 표시하고 인증상태는 변경하지 않는다. 시작 상태·복구 전체 이력, 과거 등급 스냅샷, 갱신 대상 제외/대체 및 인정 기간·유예 규칙은 추가 검증이 필요하다. 유지율과 갱신율은 산출 보류로 유지한다. 브라우저 요청으로 완전한 과거 이력 또는 확정 비율을 지정할 수 없다.

상단 가상 예제 선택을 공유하지만 인증 연결용 예제는 고객 유입 예제와 다른 모수라고 명시한다. 실제 DB 자료와 섞지 않는다. 인증 이력 점검 CSV를 별도로 제공하고 실패를 0건으로 표시하지 않는다. 직원 권한·세션·MFA·캐시 금지를 적용하며 데이터 수정·외부 AI 호출·추가 SQL은 없다. 기존 연결 필드나 테이블이 미적용이면 오류로 표시하며 대체 숫자를 만들지 않는다. 운영 DB 권한과 실제 이관 자료의 대조는 별도다.

### 표준별 접수 변화와 현재 등급 분포

2026-11-20 신규 비교의 서버 집계에 표준별 접수 고객 변화, 선택 접수 집단의 현재 등록 등급 분포, 규칙 기반 마케팅 검토 메모를 추가했다. 동일 조회 결과에서 계산하며 외부 AI 호출·모델 학습·광고 집행은 없다. 응답 버전은 ACQ-02, 검토 규칙 버전은 MKT-01이다.

표준별 접수 고객은 해당 비교기간에 접수한 고유 후보자 수이며 갱신·재신청도 포함한다. 월별 고유 고객을 단순 합산하지 않고 기간 전체에서 다시 중복 제거한다. 전년도와 올해를 같은 종료일까지 비교하며 전년 값이 0이면 증감률을 만들지 않는다. 이 비율은 확정 신규 고객 증가율·고객 유지율·시장점유율이 아니다. 표준 선택으로 월별 비교 차트를 바꿀 수 있다.

현재 등급 분포는 이번 접수 기간에 연결된 Job의 현재 등록 등급으로 묶는다. 분야·표준·등급별 고유 고객 수, Job 수와 Job 구성비를 제공한다. 과거 당시 등급·월말 등급·상향 이동률은 복원하지 않으며 ISO와 K-Beauty의 등급을 하나의 서열로 합치지 않는다.

검토 메모는 두 기간 중 큰 쪽의 접수 고객이 5명 이상인 표준에서 감소·증가 규모가 큰 대상을 각각 최대 하나씩 표시한다. 한쪽 기간 5명 미만은 별도로 경고한다. 이 기준은 통계적 유의성이나 외부 전송용 익명성 기준이 아니다. 표본 부족, 변동 없음, 대상 없음은 별도 문구로 처리한다. 관찰·추가 확인·검토 활동을 분리하며 각 관찰은 표준별 근거 ID와 연결한다. 비용·캠페인·유입 경로가 없는 상태에서 인과 효과, 수익 예측이나 예산 배분을 만들지 않는다.

수신 시 기간·집계값·비율을 검증하고 같은 규칙으로 요약을 재구성해 원래 결과와 일치하는지 확인한다. 조건 변경 시 이전 화면과 내보내기를 제거하는 기존 보호를 유지한다. 표준 100개·현재등급 그룹 300개·응답 1MiB 한도를 초과하면 범위를 줄이도록 요청하며 조용히 잘라서 반환하지 않는다. 별도 CSV에도 비교기간·집계 기준·과거 등급 보류·규칙 기반 표시를 포함한다. 신규 SQL과 외부 AI 설정은 필요하지 않다.

### AI 집계 보호 미리보기와 연결 준비 상태

2026-11-20 마케팅 검토 요약 아래에 AI 집계 보호 미리보기를 추가했다. 실제 전송 함수와 POST 생성 API는 제공하지 않는다. API 키·모델 환경변수가 있어도 전송은 강제 비활성이다. 이 기능은 전송 허가나 익명성 인증이 아닌 검토용 후보 구성이다.

서버 미리보기는 직전 마감 연도와 그 전년의 전체 집계를 기존 집계 API에서 내부 함수 호출로 다시 계산한다. 브라우저의 숫자·연도·파트너·세부 필터는 받지 않는다. 직원 권한·세션·MFA 검사를 적용하고 실패 시 후보를 만들지 않는다. 이름·생년월일·연락처·주소·경력·학력·원문·ID·등급·실제 파트너명·검토 문장은 후보 속성에 포함하지 않는다.

최초 보호 검토 규칙은 정적 검증 카탈로그에서 확인된 표준 코드만 사용한다. 양쪽 기간 중 하나라도 5명 미만인 표준은 두 값 모두 제외한다. 남은 값은 5명 단위 구간으로 바꾸며 정확 인원·합계·월별값·증감률은 넣지 않는다. 제외 그룹 수는 내부 진단으로만 표시하고 후보 JSON에서는 제외한다. 동적으로 추가한 미검증 표준명은 임의의 코드로 바꾸지 않고 제외한다.

후보 데이터가 없으면 빈 전송 자료를 만들지 않는다. 가상 보호 예제는 별도 큰 집계·작은 집단·미승인 표준을 사용하고 JSON에도 SYNTHETIC 표기를 유지한다. 검토용 JSON 다운로드는 허용 속성만 담은 후보 객체만 내려받는다. 조건 변경·화면 종료·중복 실행·응답 지연 보호를 적용하며 브라우저 영구 저장은 하지 않는다.

`/api/reports/ai-marketing-readiness`는 최고관리자만 서버 키·모델 설정값의 존재 여부를 확인할 수 있다. 원문 값과 계정 ID는 반환하지 않으며 설정값의 존재를 유효성 검증 완료로 표시하지 않는다. 최고관리자 ON/OFF·변경 사유·감사 절차, 제공업체 보관 조건 확인, AI 전송 감사, 중첩 집단·반복 조회 차분 노출 검토는 미완료로 표시한다. 작은 집단 제외와 구간화만으로 재식별 위험이 해소되었다고 판단하지 않는다. 실제 전송은 이 조건을 갖춘 별도 구현 후에만 검토한다.

이번 기능은 DB 변경이나 외부 API 호출 없이 제공한다. 기존 feature_controls의 허용 ID에는 AI 전송 제어가 없으므로 기존 설정 누락을 ON으로 간주하거나 문서 생성 설정을 AI 전송 권한으로 재사용하지 않는다.

### 후속 전송 기능과 확정 지표

2026-11-20 [AI 경영 및 마케팅 분석 설계](AI_MARKETING_ANALYTICS_DESIGN.md)를 추가했다. 전년 대비 월별 신규 고객 증감, 기초 고객 집단 유지율, 갱신율, 당시 등급·표준별 추세 및 근거를 연결한 국문 AI 요약을 개발한다.

기존 접수 기간별 고객의 현재 상태 표를 과거 유지율로 바꾸어 부르지 않는다. 최초 접수 이력 범위, 정지·복구·철회 및 대체 인증의 과거 연결을 먼저 진단한다. 자료 부족은 산출 불가로 표시하고 전년 0명, 진행 월 및 잠정 갱신 대상도 별도로 처리한다.

AI 입력은 개인정보 보호 기준을 통과한 집계값으로 제한한다. 제공업체 설정과 전송은 아직 활성화하지 않는다. 추가 SQL·이관 이력 보강 필요 여부는 집계 기반 구현 단계에서 확정하며, 기존 기능에 대한 신규 SQL 불필요 안내를 이 확장 범위에 적용하지 않는다.
