# 업무기록 읽기 실패 보호

## 2026-10-04

- 공유 업무기록 조회 오류 후 hydrated가 true가 되어 초기값 자동저장이나 수동 저장이 가능했던 문제를 수정했다.
- 성공적으로 조회한 경우에만 편집을 허용한다. 편집 잠금 소유권도 계속 필요하다. 조회 성공 후 기록이 없을 때만 신규 업무 초기값을 사용한다.
- 오류·잘못된 최상위 데이터 형식·네트워크 실패 시 편집과 저장, 단계 버튼을 비활성화한다. 저장 완료 안내도 표시하지 않는다.
- 재조회 버튼은 실패 상태에서 제공한다. 정상 조회 중 편집 입력을 무조건 다시 읽는 기능은 아니다.
- 이전 신청/조회 응답은 취소 플래그로 버린다. 로컬 저장 JSON 파싱 오류도 자동저장으로 덮지 않는다.
- 회귀시험은 실제 로딩 콜백을 추출해 모의 실패·성공·빈 기록·취소·로컬 손상을 실행한다. 전체 브라우저/DB 동시성 시험, 부분 업무데이터 전체 형식 검증은 별도다.
- 새 SQL·데이터 삭제·기존 기록 수정은 없다.
