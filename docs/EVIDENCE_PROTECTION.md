# 고객 변경 사유 및 이력 보호

SQL 023은 적용 대기입니다. 기존 019 보관 열과 020 삭제 보호 이후 적용하며, 운영 DB 실행 검증 전에는 보호가 적용됐다고 간주하지 않습니다.

- 후보자 실제 값 변경에는 활성 직원과 트랜잭션 변경 사유가 필수입니다. 기존 수정/보관 RPC가 사유를 전달합니다. 직접 REST UPDATE는 사유가 없어 거절됩니다.
- audit_logs, privacy_access_logs, package_generation_receipts에 직원 INSERT/UPDATE/DELETE/TRUNCATE 권한을 제거합니다. 기존 전용 서버 함수/감사 트리거만 기록 추가를 수행합니다.
- 이력 UPDATE/DELETE/TRUNCATE는 DB 트리거도 차단합니다. 서비스 권한을 가진 일반 요청도 변경 불가합니다. DB 소유자의 특권 유지보수·트리거 제거까지 방지하는 절대 불변 저장소나 전자서명은 아닙니다.
- 보존기간이 지나도 자동 삭제하지 않습니다. 향후 승인된 파기·보존 종료 절차는 특권 운영 작업으로 별도 설계해야 합니다.
- 과거 이관의 임시 후보자 생성/삭제 경로를 제거했습니다. 동일 이메일 또는 이름+생년월일로 기존 후보자를 처음부터 사용하며 중복 매칭·이름/생년월일 충돌은 수동 검토 대상으로 거절합니다. 보관 후보자 자동 복원은 하지 않습니다.
- 이관 보완값은 기존 값이 비어 있을 때만 채우고 Job 번호를 포함한 시스템 이관 사유를 남깁니다. 사용자 입력 정정 사유와 구분되는 자동 처리 사유입니다.
- 이관 관리번호의 기존 규칙은 이번 작업에서 바꾸지 않았습니다. ISO/K-beauty 번호 체계와 모든 과거 행의 매핑 검증은 별도입니다.

검증: test-evidence-migration.mjs는 SQL 텍스트 구조 검사이며 구문 실행·DB 권한·트리거·이관 성공 시험이 아닙니다.
